# 让学习建议有据可查：D 模块中期进展

**报告人：**D 成员（董 xj，正式姓名与学号待填写）  
**项目：**基于 RAG 与多智能体协作的个性化学习诊断与推荐系统  
**阶段：**中期进展，2026 年 11 月 14 日

## 一、问题与观点

学生完成测验后，系统很容易给出“多做练习”之类的建议，但读者无法判断建议基于哪些答题事实、指向哪份课程材料，也不知道没有足够题目时是否应下结论。我负责的 D 模块试图解决这一问题。我的阶段性观点是：学习诊断中的数值事实应由可复算的规则产生，检索证据和生成式文字只应辅助解释与安排下一步。这样，系统即使遇到检索失败或模型输出不合格，仍可说明自己知道什么、缺少什么。

目前这是工程设计主张，仍需正式课程材料和学习场景验证；它不等于已经证明推荐能提高成绩。

## 二、已完成的个人工作

首先，我沿用项目约定的 B→D→C 数据链路。B 负责评分并传入已评分作答、知识点和合法资源目录。D 对每个知识点按不同有效题计数，同一题关联多个知识点时在各知识点内分别计数，重复题去重。少于 3 道题标记“证据不足”；至少 3 道题时，正确率低于 0.60 为“薄弱”，0.60 至低于 0.80 为“待巩固”，达到 0.80 为“已掌握”。“已掌握”仅指本次测验达到规则阈值，不能概括学生的整体能力。

其次，我在原有三阶段编排上完善了证据与推荐约束。C 的检索结果必须关联本次目标知识点及 B 提供的有效资源目录，重复或越界证据会被剔除并记录原因。推荐只从当前课程、可用资源中选择，每个待改进知识点最多三条；近期用过的资源会排后。报告中保留推荐所据的证据 ID、预计用时及下一步建议。没有合法资源就返回空列表，不编造标题与链接。

最后，我实现了可选的模型解释适配器。默认配置关闭模型调用；开启时，模型只能生成独立的简短行动建议，不能改写诊断数值、知识点状态或推荐资源 ID。输出必须是限定结构的 JSON，并至少引用一条已验证的证据。非法 JSON、虚构引用、越界的成绩陈述或服务故障都会回退为规则模板。当前只用模拟模型响应验证了这条分支，尚未配置真实模型调用。

## 三、如何验证与目前结果

D 模块的 26 项自动测试已通过，覆盖阈值、少样本、重复题、多知识点题、无效证据、资源筛选和模型回退。另用 12 组明确标为合成数据的固定场景逐项比较预期与实际，12 组均符合预期。0.60 与 0.80 的边界、零题、两题、全对、全错都在其中。仓库已有的三服务联调脚本在临时环境中跑通 B→D→C，报告返回 C 的 HTTP 检索证据、目录内资源推荐与复测对比，10 个集成检查点通过。

这些结果说明规则实现与接口样例可以复现。12 组场景来自人为设定，不是学生样本；“建议是否有帮助”尚未经过人工评分，更不能从一次复测差值推断推荐的因果效果。

## 四、当前限制与下一步

团队还没有最终确定课程与题库。现有联调只用“栈、队列”两个知识点、六道样例题，未达到任务书计划的 8～12 个知识点、60 道题和 20 条课程资源。B 需要确认作废题、资源状态与最近推荐记录的可信字段；C 需要确认资料版本和证据定位；A 需要确认新增报告字段如何展示。模型适配器还需在合法配置和额度下进行真实调用，并与规则模板做人工建议质量对照。

下一阶段我会先与 B、C 对齐这些字段，再用确定的课程数据补齐场景和人工量表。正式报告中会区分规则验证、接口联调与学习效果评估，保留失败样例，不把模拟通过率写成真实教育效果。
