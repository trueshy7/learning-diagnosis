# 组仓库与现有前端对齐评估

日期：2026-11-05。对照对象：`learning-diagnosis-gh/member-a-frontend`、B/C/D 源码及协作文档，与 `code/frontend` 的已有实现。

## 结论与边界

需要修改，重点是接口与交付结构对齐；不需要重写已有页面，也不建议直接用组仓库的简化骨架替换已有成果。

现有前端在模拟环境中已经实现更完整的教师维护、单多选、作答草稿、诊断轮询、引用阅读、分页和自动化测试。但它依据此前的 frontend-contract-v1.1 建设，而组仓库 B 实际实现的是另一套最小协议。此前“真实 B/C/D 尚未提供”的背景现在已有变化：目录内已有 B/C/D 起步服务源码，但尚未与我们的完整前端联调。

本次是静态源码核对，未安装组仓库依赖、未启动服务、未执行其测试、未修改业务源码、未替换 A 目录、未提交或推送 GitHub。仓库中原有验证记录不能算作本次验证结果。

## 依据

- 组仓库 `README.md`、`docs/协作接口.md`：A 只访问 B，目录和标识保持一致，当前为六题起步流程。
- A 的 `README.md`、`docs/开发说明.md`、`src/types/api.ts`：说明起步协议和待补功能。

- 现有前端的 `src/api/client.ts`、`contracts`、`services`、`endpoints.ts`、`stores/auth.ts`、`vite.config.ts`。

文档中的六周安排和实现建议属于组内背景，不意味着本次要求重做六周工作。对接口冲突以实际源码为证据，提交团队确认；不能默认此前 A 的协议草案已被 B 接受。

## 必须解决的阻塞

| 优先级 | 项目         | 组仓库当前实现                                                                | 现有前端                                                                                 | 处理建议                                                                                            |
| ------ | ------------ | ----------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| P0     | 成功响应     | 数值 `code:0`                                                                 | 要求字符串 `code:"OK"`                                                                   | 在独立适配层明确处理数值协议；不能只把成功判断放宽而忽略 DTO                                        |
| P0     | 登录         | user 为 `{id,username,role}`，token_type 为 `bearer`，无 expires_at           | 要求 user_id/display_name、`Bearer`、expires_at；登录后立即请求 `/auth/me`               | B 补 `/auth/me`、过期时间并统一字段，或 A 单独实现骨架会话策略；不可伪造 token 过期时间             |
| P0     | 课程与题目   | 课程 `{id,name,description}`；`GET /courses/{id}/questions`                   | 课程字段不同；需 `GET /courses/{id}` 和知识点、活动测验信息                              | A 映射展示字段；B 补课程详情/知识点元数据，或先走独立最小流程                                       |
| P0     | 提交生命周期 | `POST /attempts` 一次提交 course_id、answers、baseline_attempt_id             | `POST /attempts` 先创建快照，再 `/attempts/{id}/submit` 提交                             | 两者请求及生命周期不兼容；B 的 StrictModel 禁止多余字段，直接调用会 422。必须选择协议，不能仅改 URL |
| P0     | 报告与诊断   | Attempt 内嵌 report；AI 状态与成绩分开；`POST /attempts/{id}/report` 重新生成 | 独立 `/tasks`、`/reports` 与任务轮询                                                     | A 增加骨架专用报告流程，或 B 提供快照/任务/报告接口。不能虚构任务 ID 与服务进度                     |
| P0     | 历史与时间   | `/attempts` 返回数组，created_at 是 Unix 秒                                   | `/reports` 分页对象，时间是 ISO 字符串                                                   | 转换秒到日期需要乘 1000；数组分页只能明确标记为过渡方案，正式分页需 B 实现                          |
| P0     | 报告字段     | sample_count/accuracy/status、evidence、explanation；模式 rule_template_demo  | question_count/correct_rate/mastery_status、evidences、summary；要求版本和归属等更多字段 | 明确映射可转换字段；后端缺失的版本、快照、判分明细不能随意补假值绕过校验                            |
| P0     | 比较单位     | delta 是比例，例如 0.5                                                        | delta_percentage_points，例如 50                                                         | 若采用映射，应乘 100；不重复乘；空值保留 null                                                       |
| P0     | 教师管理     | 仅概况计数及 POST 文本资源导入                                                | 课程/知识点/题库/资源 CRUD、学生报告、文件上传等                                         | 这些完整页面依赖的后端接口尚不存在；先约定扩展并由 B 提供，或明确暂不可用                           |
| P1     | 退出         | 返回 `{logged_out:true}`                                                      | 要求 data:null                                                                           | 修改专用适配或由 B 统一，不然退出撤销成功仍可能显示错误                                             |
| P1     | 错误         | 数值业务码；422 明细在 data.errors，loc/msg                                   | 字符串业务码；errors 使用 field/message                                                  | 规范化常见 HTTP 状态和字段错误，保留 request_id 用于排查，普通展示继续使用安全中文提示              |
| P1     | 资源与来源   | 证据返回文本、出处、位置及 ID；无 B 的资源详情/文件下载路由                   | 点击证据访问 `/resources/{id}` 和 `/file`，带版本                                        | B 补权限受控的来源接口。source 是文字，不得自动当 URL；缺接口时只显示原有片段                       |
| P1     | 推荐练习     | 推荐仅资源 ID、标题、原因                                                     | 推荐含可作答题目并可创建 practice 测验                                                   | B/D 提供真实推荐题与组卷能力后启用；不能将固定六题冒充个性化练习                                    |
| P1     | 教师文本导入 | 必须提供 resource_id/document_id/text/source，返回 C 导入结果                 | 提交 kind/text_content/active 等资源 DTO，期待完整 Resource                              | 为此单独设计表单/映射或扩展 B；导入成功不代表 B 的硬编码推荐目录已自动更新                          |

掌握阈值本身一致：少于 3 道为证据不足，足够样本下小于 0.6 为薄弱、0.6 至小于 0.8 为待巩固、至少 0.8 达到阈值。差异主要是 `needs_practice` 与 `consolidating` 的枚举名；前端可显式映射，但真实模式不应重算后端结论。

## 已有成果应保留

学生/教师页面框架、组件样式、单多选交互、草稿和提交意图保护、中文错误、空态与加载态、引用片段、图表、展示与调试隔离、教师停用确认及现有测试都可保留。测试中的模拟数据通过不等于已兼容组仓库 B；适配后须增加使用真实 B/C/D 的验证。

不要照搬骨架中“原样显示 trace/标识”的呈现方式到普通界面。保留真实来源和模式说明，内部字段、原始英文错误及轨迹仍按展示需求处理。规则模板和关键词检索必须如实标识，不能写成已完成 LLM 或向量检索。

## 推荐实施路线

1. 先与组长/B 确定两阶段目标：用仓库现有协议跑通最小真实流程；完整功能由团队协商扩展接口。
2. 若最小闭环是近期目标：新增明确的骨架后端适配和对应测验/报告状态，不直接把简化响应硬塞进完整 DTO。保留当前完整 mock 供展示和后续功能开发，严格禁止真实失败回落 mock。
3. 若近期要求全功能：优先评审此前完整接口文档，让 B 选择接收或提出修改，再同步前端、B 和 C/D，不能由 A 单方面要求 B 全量照做。
4. 首批验收：真实登录、课程取题、六题提交、断网重试沿用幂等键、成绩已保存但诊断失败、报告重生成、历史、固定基线复测、学生访问教师接口被拒绝。
5. 第二批验收：课程题库维护、多选判分、测验快照与历史稳定、分页、资源归档与授权阅读、文档上传处理、推荐练习、教师授权学生报告。

## 目录与交付调整

- 最终源码放组仓库的 `member-a-frontend`，保持团队目录；先合并核对再替换骨架，不将整个 `code` 或 `node_modules` 直接覆盖进去。
- 现有 docs:api、格式检查和截图路径用 `../docs`，迁入后会指向组仓库公共 docs。应迁为 A 自己的 `docs` 或独立子目录并同步脚本，避免覆盖组公共材料。
- 将自己的完整接口文档与联调说明放 A 的 docs；公共协作接口变更须与组员确认，保留两阶段协议边界和版本，不能留下两份互相冲突却都声称权威的文档。
- 当前使用 npm/package-lock，骨架已有 pnpm-lock。提交时选定团队认可的包管理器；不要把两个过期锁文件一起保留。现有 Vue/Pinia/Vite 版本较新，若 A 独立安装无需为其它 Python 模块降级，但要记录 Node 要求与实际验证版本。
- 现有默认 mock、独立 real 端口 5174 和 Vite 代理可保留；`.env` 使用 VITE_API_MODE，不能照搬骨架 VITE_USE_MOCK 后以为已切换成功。若改为跨域直连 5174，B 当前默认仅允许 5173，需要补 CORS；保留同源代理则通常无需改跨域来源。
- B 的 CORS 当前只允许 GET/POST/DELETE；未来跨域 PATCH 管理接口要同步放行。
- 补齐忽略 `.env.local`、`.env.*.local`、测试输出和截图中不应提交的内容；不提交 node_modules、dist、真实数据或密钥。公开无密钥的模式配置与官方 MSW worker可按项目需要提交。
- 组仓库根 README 的启动方式和账号应随合并更新；当前骨架账号 student/teacher、demo12345 与旧前端 mock 的 demo_*、Demo123! 不同，不能混用。
- 当前目录未看到 .git 元数据，本次不能据此确认远端、分支或推送权限。正式上传应在实际克隆的仓库中核对 remote 和分支，按团队约定提交，不直接推主分支。
