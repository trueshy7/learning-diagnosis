# 成员 A 开发说明

## 一、负责范围与第一阶段目标

A 负责学生端与教师端的交互呈现，把 B 返回的业务数据转换为清楚、可操作的学习流程。第一阶段先跑通“登录 → 选课 → 测验 → 报告 → 推荐与引用 → 历史 → 复测”，为后续真正的 RAG 与多智能体服务提供界面入口。

前端不计算真实诊断结论，也不决定引用来源。真实模式中，B 评分并调用 C、D，前端只接收最终报告。`mock.ts` 的固定规则是离线界面开发工具，不作为系统算法实现。

## 三、接口约定

所有路径以 `VITE_API_BASE_URL` 为前缀，默认真实接口前缀为 `http://127.0.0.1:8000/api/v1`。响应统一为：

```json
{"code":0,"message":"ok","data":{},"request_id":"..."}
```

成功 `code=0`；失败需要非零业务码及适当 HTTP 状态。登录之外的接口使用 `Authorization: Bearer <token>`。`request_id` 会随错误展示，便于与 B 的服务日志对照。

| 方法与路径 | 请求 / 响应 data | 页面 |
| --- | --- | --- |
| POST `/auth/logout` | B 已提供，当前前端只清理本地会话，待接入服务端撤销 | 后续认证迭代 |
| POST `/attempts/{id}/report` | B 已提供重新生成，当前未提供按钮 | 后续报告迭代 |
| POST `/auth/login` | `{username,password}` → `{access_token,token_type,user}` | 登录 |
| GET `/courses` | `Course[]` | 课程 |
| GET `/courses/{id}/questions` | `{questions: Question[]}`，不含答案 | 测验 |
| POST `/attempts` | `{course_id,answers,baseline_attempt_id?}` → `Attempt` | 提交 |
| GET `/attempts` | `Attempt[]` | 历史 |
| GET `/attempts/{id}` | `Attempt` | 报告 |
| GET `/teacher/overview` | `{user_count,question_count,attempt_count,resource_count}` | 教师 |

测验提交的 `Idempotency-Key` 请求头由页面进入时生成；首次提交固定答案快照，失败重试沿用同一键与原快照，成功进入报告后新测验重新生成键。B 为同一键保存稳定记录；不同答案复用原键会返回 409。当前页面刷新与离开后不恢复键，后续可与作答草稿一并持久化。

完整字段声明在 `src/types/api.ts`。`accuracy`、`before_accuracy`、`after_accuracy`、`delta` 使用 0～1 的比例（`delta` 可以为负）；`percentage` 使用 0～100 的测验得分率。`null` 表示没有足够证据，不能转换为 0。比较变化以“百分点”展示。

题目 `kind` 当前只接入 `single`。提交答案格式：

```json
{
  "course_id":"course-ds",
  "answers":[{"question_id":"q-stack-1","selected_option_ids":["A"]}],
  "baseline_attempt_id":"可选的同课程历史测验 ID"
}
```

当 D 未启动或调用失败时，B 仍保存成绩，返回 `status=completed`、`report=null`、`ai_status=unavailable` 与 `ai_message`。此时前端展示已保存成绩和诊断服务未可用提示，不伪造诊断、引用或推荐。D 正常返回时 `ai_status=completed`，`report` 为完整报告。`baseline` 的评分可以保存，但若基线没有报告，则知识点比较可能为空。

`ai_status` 可为 `completed`、`unavailable`、`disabled`、`processing`。`processing` 表示成绩已保存但报告尚未完成；前端应允许从历史再次查看，不把它当作失败评分。`created_at` 为 Unix 秒时间戳，`baseline_attempt_id` 可空。

真实模式不要把 mock 中的正确答案、题量和知识点名字当成固定规则。题目选项与知识点由 B 提供；报告中的 `evidence`、`recommendations`、`trace` 和 `fallback_status` 原样展示。`source` 当前是文字字段，不能直接当作可点击 URL。

## 四、本地样例说明

1. `.env.local` 不存在时默认进入本地样例；样例不会发起 HTTP 请求。
2. 学生与教师账号仅为固定演示账号，密码相同：`demo12345`。
3. `course-ds` 中有三道单选题，分别用于栈、队列和二叉树的页面验证。
4. 每个知识点只有一道题，正确率仅反映本次样例作答；诊断状态一律为 `insufficient_evidence`。
5. 样例报告只有一条固定引用材料，错题会产生对应的基础复习建议。这不是 RAG 检索结果。
6. 同一账号历史数据保存在 `localStorage`。复测选择基线后，样例计算正确率差值。
7. 本地教师概况中的用户、题目、资源数量为固定样例，测验数量只读取当前教师的本地记录。

## 五、接入真实服务的顺序

1. B 启动后端并准备账号、课程、题目种子数据。
2. A 将 mock 开关设为 `false`，重启 Vite，退出后重新登录。
3. 先验证登录、课程、题目接口，再验证测验提交与报告结构。
4. 与 C 检查引用的 `document_id/resource_id/chunk_id/location/source/title` 是否在报告中保持一致。
5. 与 D 检查空证据、样本不足、正常报告和降级报告的交互，以及复测字段的比例单位。
6. 对照 B 的 `request_id` 定位失败请求；确认 HTTP 401、403、422、500 以及超时均有可理解的提示。
7. 最后补充管理端功能。新增字段先写入接口契约，再更新 `types/api.ts`、mock、服务和页面。

## 七、手动验收场景

- 本地样例：学生登录 → 选课 → 任意选择答案 → 提交 → 查看分数、知识点、引用与推荐。
- 历史复测：进入历史 → 打开报告 → 点击复测 → 改变答案 → 检查基线、本次和变化值。
- 证据不足：样例所有知识点显示“证据不足”，不能把一道题当作掌握度结论。
- 权限：学生导航不显示教师概况；直接访问教师路由会回到课程；真实服务还必须返回 403。
- 错误账号：密码错误时保留表单并显示提示，不进入课程。
- 真实服务停机：关闭 mock 后停止 B，应显示连接失败；页面不得偷偷展示样例数据。
- 报告引用：显示后端返回的标题、来源、位置和标识，不生成不存在的链接。
- 窄屏与键盘：约 375px 宽度可阅读；表格可横向滚动；Tab 键可以访问选项与按钮。
- 重试幂等：首次提交后模拟网络失败，点击“重试提交”，检查两次请求的 `Idempotency-Key` 和请求体一致；历史记录只出现一条。重新进入新测验时键应不同。
- 构建：`npm run build` 通过后，再运行 `npm run preview` 检查路由与页面。

## 八、后续设计注意点

需要图表时可引入 ECharts，在 `components/` 中建立专门组件；只对非空、样本足够的数据作图，并保留表格。需要统一组件库时可选择 Element Plus，但应先统一全组版本和主题，避免同时维护多套控件。初始工程使用基础 CSS，减少依赖与上手成本。

当前没有自动化界面测试。正式实现复杂状态、评分相关交互或多题型后，再补充围绕用户行为的测试。不要编写只重复组件实现细节的测试。
