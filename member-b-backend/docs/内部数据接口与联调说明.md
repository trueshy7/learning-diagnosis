# B 内部数据接口与 C/D 联调说明

本文描述当前已经实现的 B 数据出口，契约标识为 `b-internal-1`。B 提供资料、版本、索引状态和历史测验数据；C 负责主动同步、分块、索引及检索，D 负责诊断和推荐。B 另已实现诊断通知任务、冻结输入和独立 worker 向 D 交付 ID，见 [诊断任务交付说明](诊断任务交付说明.md)。B 不调度 C 同步，也未保存最终诊断报告。

现有教师/学生接口继续使用用户 Token。内部接口使用独立的服务凭证，不能将用户 Token 作为 C/D 凭证。新接口也不是 C/D 现有严格请求模型的直接替代；接收方需按本契约增加适配。

## 1. 启用与迁移

1. 已有数据库先在维护窗口停止业务写入，修改 [create_resource_index_states.sql](../sql/create_resource_index_states.sql) 的 `USE` 库名并完整执行。它创建状态表，将缺少状态记录的历史资料（包含软删除资料）初始化为 pending；重复执行不会覆盖已有回报。DDL 会隐式提交，整份脚本不可作为单个事务回滚。
2. 在本地 `.env` 填写下列配置。分别运行两次 `python -c 'import secrets; print(secrets.token_hex(32))'` 生成独立随机密钥，分发给对应服务。不要写入 Git。
3. 重启 B，刷新 `/docs`。内部接口的 Authorize 使用 `InternalServiceBearer`，填写对应服务密钥。

```dotenv
C_SERVICE_KEY=填写C独立随机密钥
D_SERVICE_KEY=填写D独立随机密钥
C_SERVICE_COURSE_IDS=demo-course-ds-teacher-2,demo-course-python-teacher-2
D_SERVICE_COURSE_IDS=demo-course-ds-teacher-2,demo-course-python-teacher-2
```

密钥至少 32 个 UTF-8 字节，C/D 不能相同；密钥未配置、过短或相同时，对相应内部接口的带凭证请求返回 503。凭证缺失/错误返回 401。课程白名单使用英文逗号分隔；空白代表没有课程权限；显式 `*` 允许所有课程，包括以后新增的课程。服务账号的课程授权由部署配置管理，不由请求方提交 teacher_id 或 student_id 绕过。

新库启动时会自动创建状态表。`create_all` 不会回填历史数据；未回填的资料对外视为 pending，首次实际更新或有效 C 回报时也可创建状态行。建议已有库仍执行上述迁移以完整初始化。数据库列的字符集/排序规则应与父表 `course_resources.id` 一致。

## 2. 路由与公共规则

默认 B 地址 `http://127.0.0.1:8000`，没有 `/api/v1` 或 `/internal/v1` 前缀。

| 方法 | 路径 | 凭证 | 用途 |
| --- | --- | --- | --- |
| GET | `/internal/courses` | C | 分页查询允许同步的课程 |
| GET | `/internal/courses/{course_id}/resources` | C | 分页资料清单，包含 deleted 墓碑 |
| GET | `/internal/resources/{resource_id}` | C | 当前资料正文及索引状态 |
| PUT | `/internal/resources/{resource_id}/index-state` | C | 回报当前版本索引/删除结果 |
| GET | `/internal/attempts/{attempt_id}/diagnosis-input` | D | 完整已结束测验诊断输入 |
| GET | `/internal/diagnosis-tasks/{task_id}/input` | D | 正式任务冻结输入，字段与通知契约见任务文档 |

四个 C 接口不接受 D 密钥；D 接口不接受 C 密钥。越课程和不存在的数据均返回 404。所有成功返回 HTTP 200，统一包装如下，调用方读取 `data`：

```json
{"code":0,"message":"ok","data":{},"request_id":"追踪ID"}
```

时间为 Unix 秒。索引回报使用 JSON，禁止额外字段；版本严格为整数。错误继续沿用 B 的 HTTP 状态、code、message、data、request_id，不返回数据库连接或原始异常信息。

## 3. C 获取课程和资料清单

两个列表接口均接受 `limit`（默认 100，1～100）和 `after_id`（可选，上页返回的最后 ID，1～64 字符）。响应为 `items`、`next_after_id`；后者为 null 表示本轮结束。分页使用数据库 ID 排序和 `id > after_id`，不是偏移分页。

课程清单不限制发布状态：draft 可提前建立索引，archived 仍有阅读用途。是否允许学生使用课程由 B 的学生业务授权控制，C 也应按其检索调用契约限制范围。

```json
{
  "items": [
    {"id":"demo-course-ds-teacher-2","name":"数据结构基础","status":"published","updated_at":1794800000}
  ],
  "next_after_id": null
}
```

资料清单不加载正文，只返回以下字段：

```json
{
  "items": [
    {
      "id":"资料ID","course_id":"demo-course-ds-teacher-2","title":"栈资料",
      "version":2,"status":"active","index_status":"pending","updated_at":1794800000
    }
  ],
  "next_after_id": null
}
```

**本版采用周期性完整扫描，再按版本处理变化**，不提供基于 updated_at 的增量保证。每轮从不带 after_id 开始，扫描全部授权课程和资料；并发新增落在已扫描范围内的 ID、扫描期间的修改会由下一轮补齐。不能将秒级 updated_at 或上轮最后 ID 当作永久同步水位。

deleted 记录保留，并始终出现在清单中。没有变更的 ready 版本无需重复索引；pending/failed 或 C 本地缺失的版本需要处理。C 自身索引丢失时，可从完整清单重建，不能仅依赖 B 的 ready 标记跳过本地不存在的数据。资料规模增大后再增加持久化变更日志。

## 4. C 获取资料正文及摘要

有效资料详情 data：

```json
{
  "id":"资料ID","course_id":"demo-course-ds-teacher-2","title":"栈资料",
  "version":2,"status":"active","updated_at":1794800000,
  "text":"栈遵循后进先出原则。","source":"教师自编教材",
  "knowledge_point_ids":["demo-kp-stack-concept"],
  "content_hash":"64位小写SHA256摘要",
  "index_state":{
    "resource_version":2,"status":"pending","indexed_version":1,
    "document_id":"旧版本文档ID","indexed_hash":"旧版本摘要",
    "last_error":null,"acknowledged_at":null
  }
}
```

B 在共享锁内读取资料、标签和状态，避免同一响应混入不同业务版本。C 使用 text 建索引，不需要再次读取 PDF/DOCX；接口不暴露 storage_key、本地路径、用户信息或原文件。

deleted 详情只返回 id、course_id、title、version、status、updated_at、index_state，不再返回 text/source/knowledge_point_ids/content_hash。C 按该版本执行删除。

摘要算法：

1. 构造仅包含 `course_id`、`title`、`text`、`source`、`knowledge_point_ids` 的对象；知识点 ID 按 Unicode 码点升序排列。
2. 对象键按字典序排列，使用 JSON 序列化：保留 Unicode 字符，不缩进，分隔符为 `,` 和 `:`；不额外裁剪或归一化正文。
3. 将 JSON 以 UTF-8 编码，计算 SHA-256，返回 64 位小写十六进制字符串。

对应实现见 `app/services/resource_index.py::content_hash`。C 可直接保存并回传 B 返回的摘要；若自行计算，须遵守同一序列化规则。版本号、资料 ID、时间和状态不参加摘要；仅更新标签、标题或来源同样会增加版本并重新同步。

## 5. C 回报索引结果

成功建立索引：

```json
{
  "resource_version":2,
  "status":"ready",
  "document_id":"C实际返回的文档ID",
  "content_hash":"B详情返回的64位小写摘要"
}
```

失败：

```json
{"resource_version":2,"status":"failed","error_code":"timeout"}
```

删除成功：

```json
{"resource_version":3,"status":"deleted"}
```

| 字段 | 规则 |
| --- | --- |
| resource_version | 必填，严格整数，1～2147483647，必须等于 B 当前版本 |
| status | ready / failed / deleted；C 不能回报 pending |
| document_id | 仅 ready 必填，去首尾空白后 1～128 字符 |
| content_hash | 仅 ready 必填，64 位小写十六进制，必须与 B 当前内容相符 |
| error_code | 仅 failed 必填，index_failed / storage_unavailable / timeout / unknown |

failed 的错误描述由 B 根据 error_code 生成，不接收原始异常、堆栈或任意 last_error，详细日志保留在 C。

响应 data 是 `index_state` 的结构。回报先锁资料，再锁状态，更新和状态回报按同一资料串行化：

- 当前 v3 收到 v2 回报：409，调用方重新读取，不盲目重试旧回报。
- 同版本、同 document_id、同摘要的 ready 重复回报：200，保留第一次确认时间。
- ready 后收到 failed 或不同 document_id 的 ready：409；一个业务版本的文档标识必须稳定。
- failed 可以重试为 ready；相同 failed 重报保持幂等。
- active 不能回报 deleted；deleted 不能回报 ready。
- deleted 可先回报 failed 表示清理失败；成功回报 deleted 后清空索引版本、文档与摘要，再来的失败回报被拒绝。
- 事务失败返回 503，数据库回滚；回报超时可按相同内容重试。

**C 只能在索引已持久化且可检索后回报 ready，在对应版本的索引已不可检索后回报 deleted。** B 信任受授权的 C 回报，不会向 C 发请求验证其索引。仅手动模拟成功回报只验证 B 的状态接口，不代表真实检索已就绪。

C 还必须持久化各资料的最高处理版本/删除墓碑：迟到的低版本写入或删除不能覆盖高版本，重复处理不能产生重复索引。B 拒绝旧回报无法替代 C 自身的索引版本保护。重建同一版本须保持 document_id 稳定；C 内部索引实现版本另行管理。

## 6. 索引状态与模型

`ResourceIndexState` / `resource_index_states` 共十列：

| 字段 | 类型 | 约束/含义 |
| --- | --- | --- |
| resource_id | VARCHAR(64) | PK、FK → course_resources.id，RESTRICT |
| resource_version | INTEGER | NOT NULL，≥1，当前需要处理的业务版本 |
| status | VARCHAR(20) | NOT NULL，默认 pending，CHECK 四种状态 |
| indexed_version | INTEGER | 可空，最近成功版本；非空时 1～resource_version |
| document_id | VARCHAR(128) | 可空，C 的稳定文档标识 |
| indexed_hash | VARCHAR(64) | 可空，最近成功的内容摘要 |
| last_error | TEXT | 可空，B 生成的脱敏错误描述 |
| acknowledged_at | BIGINT | 可空，当前版本最近有效回报时间 |
| updated_at | BIGINT | NOT NULL，服务端维护 |

ready 还有 CHECK：indexed_version 非空且等于 resource_version，document_id/indexed_hash 非空。资料存在和课程一致性由资料外键及业务读取校验保证，数据库不能跨表 CHECK 当前资料版本。

创建资料（含上传）、实际修改或首次删除时，在同一个业务事务中设置 pending。修改保留旧 indexed_version、document_id、indexed_hash 用于核对，但不能继续作为当前可用资料；清空旧错误和确认时间。无实际变化的 PATCH、重复 DELETE 不重置状态。没有状态行、状态版本不匹配或 ready 元数据不完整时，对外视为 pending。

教师/学生资料创建、上传、详情、修改和列表新增 `index_status` 字段，仅表示索引处理状态，不影响资料正文阅读或原文件下载。DELETE 响应仍使用原删除结果结构。资料业务状态仍为 active/deleted，课程状态仍为 draft/published/archived。

## 7. D 获取完整诊断输入

```http
GET /internal/attempts/{attempt_id}/diagnosis-input
Authorization: Bearer <D_SERVICE_KEY>
```

没有完成的测验返回 409，不泄露正确答案。已到截止时间但仍是 in_progress 的记录沿用现有懒结算：按最后保存答案结算为 expired 并提交，再返回数据。其他课程或不存在的测验返回 404。

| data 字段 | 含义 |
| --- | --- |
| contract_version | 固定 b-internal-1 |
| assessment_policy | 固定 kp-accuracy-v1 |
| attempt_id / exam_id / course_id | 真实业务 ID |
| attempt_status | submitted / expired |
| started_at / submitted_at | 服务器开始/完成时间 |
| score / total_score / percentage | 已评分总分、满分和百分比 |
| knowledge_points | 开始测验时冻结的知识点目录，id/name 等原始快照字段 |
| knowledge_point_stats | 已保存的知识点统计，含样本数、正确数、正确率、状态和证据题目 ID |
| graded_answers | 试卷全部题目的冻结题目、最终答案与评分，包括未答题 |
| baseline | 初测为 null；复测为历史基准信息和统计 |
| resource_catalog | 同课程、active、当前版本 ready 且摘要匹配的资料目录 |
| warnings | 无可用资料时为 ["暂无可用的课程检索资料"]，否则 [] |

graded_answers 的每项字段：

| 字段 | 含义 |
| --- | --- |
| question_id / kind / stem | 发布快照中的题目 ID、single/multiple、题干 |
| options | 选项 id/label/text，不包含 is_correct |
| knowledge_point_ids | 题目快照的知识点 |
| score / sort_order | 题目满分、展示顺序 |
| selected_option_ids | 最终保存的选项 ID 数组 |
| answered | selected_option_ids 是否非空 |
| correct_option_ids | 发布时的正确选项 ID |
| correct / earned_score / explanation | 已评分对错、实得分、发布时解析 |

未答题为 answered=false、correct=false；答错题为 answered=true、correct=false。D 使用 B 的判分，不重新根据当前题库判分；题目、选项、解析和知识点目录来自历史快照，不受后续题库编辑影响。未覆盖知识点保留 sample_count=0、accuracy=null，不能解释为掌握或不掌握。

baseline 含 attempt_id、exam_id、attempt_status、submitted_at、assessment_policy、score、total_score、knowledge_points；其中 knowledge_points 为基准测验保存的知识点统计，不是当前目录。

resource_catalog 每项包含：

```json
{
  "resource_id":"资料ID","resource_version":2,"document_id":"C文档ID",
  "content_hash":"64位摘要","title":"栈资料",
  "knowledge_point_ids":["demo-kp-stack-concept"]
}
```

资料标签取其全部关联标签与本次测验目录的交集；交集为空则排除。pending、failed、deleted、旧版本索引和摘要不匹配的资料都排除。按 attempt_id 实时导出的目录会随资料变化；正式任务在首次交付准备时冻结完整输入和摘要，重试不变，D 必须读取通知中的 task input 路径，详见 [诊断任务交付说明](诊断任务交付说明.md)。当前未保存最终报告。

D 向 C 检索时必须限定 course_id 及此目录中的 resource_id/version/document_id，引用只能来自返回的证据；指定版本不可用时 C 应明确报告，不能静默换版本。没有资料仍可基于测验统计诊断，但不能虚构资料或引用。本接口不返回 student_id、邮箱、密码、会话或原文件路径。

### 旧教师接口兼容

`GET /teacher/attempts/{attempt_id}/diagnosis-input` 保留 D 旧严格模型的最小字段，resource_catalog 仍为空，不新增完整答案、版本和 warnings。它与新接口共用历史评分读取。需要真实资料目录和完整题目时使用新内部契约；不能把新响应直接传给 D 旧模型，否则 extra=forbid 会返回 422。

## 8. 联调流程

先按现有资料文档创建/上传资料，记录真实 course_id、resource_id；按测验文档让学生提交一份测验，记录真实 attempt_id。

在本地终端设置 B 地址和对应密钥（实际密钥不要写入示例文件或提交仓库）：

```sh
export B_URL=http://127.0.0.1:8000
export B_C_KEY='本地配置的C密钥'
export B_D_KEY='本地配置的D密钥'

curl "$B_URL/internal/courses" -H "Authorization: Bearer $B_C_KEY"
curl "$B_URL/internal/courses/demo-course-ds-teacher-2/resources" -H "Authorization: Bearer $B_C_KEY"
curl "$B_URL/internal/resources/替换为真实资料ID" -H "Authorization: Bearer $B_C_KEY"
curl "$B_URL/internal/attempts/替换为已完成测验ID/diagnosis-input" -H "Authorization: Bearer $B_D_KEY"
```

第一次 D 导出没有资料目录是正常的。C 需要实现以下适配循环，而不是直接把 B 整个包装发送给其原 ingest 模型：

```text
遍历授权课程 → 遍历全部资料清单
  deleted：执行带版本保护的索引删除 → PUT 回报 deleted
  active 且需要处理：GET 最新详情 → 持久化索引 → PUT 回报 ready
  处理失败：PUT 回报 failed + 受支持 error_code，稍后重试
  回报 409：丢弃旧结果并重新读取当前资料
本轮结束，下一轮从课程和资料清单第一页重新扫描
```

C 完成真实同步后，检查教师详情 index_status=ready，再由 D 导出确认目录出现该资源。随后修改资料验证 pending/版本递增/旧回报 409；重同步后再次 ready。最后删除资料，验证 B 目录立即排除、清单保留墓碑、C 删除后回报 deleted。

B 现已在测验结算时自动持久化通知任务，由独立 worker 将 attempt_id、task_id 和冻结输入路径交给 D。D 需实现新的接收端；启动命令、双向凭证、重试和学生/教师任务查询见 [诊断任务交付说明](诊断任务交付说明.md)。最终报告回传、保存与学生报告查询仍待后续，不能把服务密钥交给浏览器。

## 9. 验证与限制

```sh
python -m pytest -q tests/test_internal.py tests/test_resources.py tests/test_resource_files.py tests/test_exams.py
python -m pytest -q tests/test_mysql_internal.py
```

默认测试使用会话替身和 MySQL 方言，覆盖 C/D 权限隔离、课程白名单、清单、摘要、回报幂等、旧版本拒绝、修改/删除失效、完整历史诊断和错误脱敏。

真实 MySQL 测试须显式配置 TEST_MYSQL_URL，由 `tests/test_mysql_resources.py` 的夹具创建随机独立测试库，验证真实 CRUD、状态与正文同事务回滚、行锁后的迟到回报、迁移重跑和真实测验导出，结束后删除随机库；不会使用 DATABASE_URL 业务库。测试账号需要建库、删库和表读写权限。没有 TEST_MYSQL_URL 时跳过，不能把替身测试当作真实 MySQL 或 C/D 端到端联调成功。

本阶段未实现：C 的拉取工作进程/定时器、C/D 原服务新模型、D 任务接收端、向量索引、RAG 检索代理、诊断完成回调和报告落库、消息队列、资料硬删除及严格增量同步。这些分别属于接收成员或后续业务阶段；B 自动入队、通知投递和冻结输入已实现。
