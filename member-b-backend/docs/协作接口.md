# 四人协作接口

## 调用主线

浏览器A只访问B的 `/api/v1`；B管理登录、权限与业务记录，调用D的 `/internal/diagnose-and-recommend`；D调用C的 `/internal/retrieve`。教师经B的 `/api/v1/teacher/resources` 把文本交给C。C、D的内部接口用于本机开发，后续部署需增加内部服务认证。

| 成员 | 包名或目录 | 地址 |
| --- | --- | --- |
| A | `src/` | `http://127.0.0.1:5173` |
| B | `backend_service` | `http://127.0.0.1:8000` |
| C | `rag_service` | `http://127.0.0.1:8001` |
| D | `diagnosis_service` | `http://127.0.0.1:8002` |

## 共用数据标识

课程 `course-ds`；知识点 `kp-stack`（栈）、`kp-queue`（队列）；资源 `res-stack`、`res-queue`；文档 `doc-stack`、`doc-queue`。C实际返回的片段和证据ID由其稳定切分规则生成，不在A中猜测或重造。

B的演示课程首次启动导入六道题：`q-stack-1` 至 `q-stack-3`、`q-queue-1` 至 `q-queue-3`。教师现在可通过 B 的接口创建新课程、知识点和单选题；随机组卷及难度标签尚需建设。

## 业务响应

```json
{"code":0,"message":"ok","data":{},"request_id":"..."}
```

`data`按接口可为对象或数组。失败使用相应HTTP状态与非零code。登录返回Bearer令牌，其他业务请求带 `Authorization: Bearer <token>`。`/health` 及C/D内部接口直接返回JSON，不包此层。

提交测验：

```json
{"course_id":"course-ds","answers":[{"question_id":"q-stack-1","selected_option_ids":["A"]}],"baseline_attempt_id":null}
```

演示课程初始六道；新课程按当前数据库题库计分，未答题计错。返回原始 `score`、`max_score`、`percentage`、`status` 和 `report`。诊断不可用时 `report` 为null，`ai_status` 和 `ai_message` 指明原因，成绩已保存。A必须显示此状态。需要幂等重试时沿用同一个 `Idempotency-Key`。复测基线必须来自同一课程。

## B 的中期课程接口

| 接口 | 权限 | 响应说明 |
| --- | --- | --- |
| GET `/courses` | 登录用户 | 数据库中的课程数组 |
| GET `/courses/{course_id}/knowledge-points` | 登录用户 | `course_id`、`items`；每项有 `id`、`name`、`question_count` |
| GET `/courses/{course_id}/questions` | 登录用户 | 题目数组，隐藏 `correct_option_ids` |
| POST `/teacher/courses` | 教师 | 创建课程，字段 `id`、`name`、`description` |
| POST `/teacher/courses/{course_id}/knowledge-points` | 教师 | 创建知识点，字段 `id`、`name` |
| POST `/teacher/courses/{course_id}/questions` | 教师 | 创建单选题，字段 `id`、`stem`、`kind`、`options`、`correct_option_ids`、`knowledge_point_ids` |
| GET `/teacher/courses/{course_id}/questions` | 教师 | 题目数组，包含标准答案 |

以上路径均以 `/api/v1` 为前缀。新建课程需要先建知识点、再建题。题目的知识点必须属于其课程。A 可接入这些教师接口建设管理页面；当前 A 仍只有概况页。

### 成员 B 的功能扩展接口

| 接口 | A/C/D 协作约定 |
| --- | --- |
| GET `/courses/{course_id}/wrong-questions` | A 展示本人的当前错题，`available_for_practice` 标明题目是否仍启用。 |
| GET `/courses/{course_id}/practice?knowledge_point_id=...&limit=10` | A 使用返回的 `question_ids` 和隐藏答案的 `questions` 组织练习。 |
| POST `/attempts`，附 `question_ids` | 指定启用题子集计分并标记 `kind=practice`；不附时仍为全课程测验。B 继续给 D 发送该次题目的判分数据。 |
| GET `/attempts/{attempt_id}/review` | 仅本人可查看提交时的题目与答案快照；旧记录可能返回 `snapshot_available=false`。 |
| GET `/courses/{course_id}/progress` | A 可用 `timeline` 和 `knowledge_points` 绘图；同时包含测验与练习，逐条带 `kind`。 |
| PATCH `/teacher/courses/{course_id}/questions/{question_id}` | 教师完整更新题目，已存历史快照保持原样。 |
| PATCH `/teacher/courses/{course_id}/questions/{question_id}/status` | `{"active":false}` 停用，`true` 启用；学生取题只返回启用题。 |
| POST `/teacher/resources/file` | JSON Base64 文件导入，支持 `.txt`、`.md`、可提取文字的 `.pdf`；B 提取文字后调用 C 的 `/internal/ingest`。 |
| GET `/teacher/resources`、GET `/teacher/resources/{id}/status`、DELETE `/teacher/resources/{id}` | B 维护资料目录与索引状态；删除先调用 C，再在 B 软删除。 |
| POST `/courses/{course_id}/ask` | B 调用 C 的 `/internal/retrieve` 并返回原文摘录和 `citations`；`mode=extractive_retrieval`，没有证据时 `status=insufficient_evidence`。此接口不调用 LLM。 |

路径同样以 `/api/v1` 为前缀。A 当前尚未接入新增页面；新接口详见项目根目录 `成员B_功能扩展实现记录.md`。

## B到D

输入包含 `attempt_id`、`course_id`、`graded_answers`、`knowledge_points`、`resource_catalog`，复测可加 `baseline.knowledge_points`。每条已判分记录为：

```json
{"question_id":"q-stack-1","knowledge_point_ids":["kp-stack"],"correct":true}
```

D输出 `knowledge_points`、`evidence`、`recommendations`、`explanation`、`comparison`、`trace`、`fallback_status`。诊断状态为 `insufficient_evidence`、`weak`、`needs_practice`、`mastered`。少于3道不同有效题为证据不足；达到3道后，正确率小于0.60为薄弱，0.60至小于0.80为待巩固，大于等于0.80为本次测验达到掌握阈值。零题的accuracy为null。

目前 `mode=rule_template_demo`，未调用LLM。推荐资源ID必须来自B提供的目录，不能由生成文本创造。复测仅比较双方样本均不少于3的同一知识点。

## D到C

```json
{"course_id":"course-ds","query":"栈 概念与练习","knowledge_point_ids":["kp-stack"],"top_k":5}
```

响应字段 `mode`、`index_version`、`evidence`。每条证据包含 `evidence_id`、`document_id`、`resource_id`、`chunk_id`、`knowledge_point_ids`、`text`、`score`、`location`、`source`、`title`。

C当前是 `keyword_demo`，检索分数是排序信号，不是可信概率。D设 `RAG_MODE=http` 才会访问C；默认mock为独立开发样例，会在报告中显式标明。HTTP失败不得悄悄切回mock并声称调用成功。

## 变更规则

先更新此文档和一组请求响应样例，再修改调用方。字段新增尽量兼容，删除和更名必须同步A/B/C/D。业务分数与掌握度分别统计，不能把未覆盖知识点画成0分。
