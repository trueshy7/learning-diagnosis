# 四人协作接口

A 负责前端，B 负责账号、课程、题库、试卷、作答成绩和资料业务，C 负责知识库与 RAG 检索，D 负责学习诊断及推荐。本文描述当前 B 的实际能力，代替历史 `/api/v1` 和静态演示数据约定。

当前采用 C 主动拉取、回报状态，B 向 D 通知诊断任务、D 获取冻结数据的方案。实际数据路径为 `/internal/...`，详见 [内部数据接口与联调说明](内部数据接口与联调说明.md) 与 [诊断任务交付说明](诊断任务交付说明.md)。历史 [B、C、D 数据契约 V1](BCD数据契约V1.md) 不作为本阶段运行契约。

## 当前调用关系

| 调用方 | 接收方 | 当前状态 |
| --- | --- | --- |
| A 浏览器 | B，默认 8000 | 调用 /user、/teacher、/courses、/exams、/attempts，无 /api/v1 前缀 |
| B | C，默认 8001 | 尚无业务路由接入；保留 clients.py 客户端 |
| B | D，默认 8002 | 已实现任务通知 worker；D 需新增 /internal/diagnosis-tasks 接收端 |
| C | B，默认 8000 | 已提供课程/资料清单、正文和索引回报接口；需 C 实现拉取进程 |
| D | B，默认 8000 | 已提供完整实时导出和任务冻结输入；需 D 适配 b-internal-1 |

当前课程、知识点、题目、作答及资料正文来自 MySQL；PDF/DOCX 原件另保存在 B 的私有目录。资料管理见 [资料业务接口说明](资料业务接口说明.md)，上传与鉴权下载见 [资料文件上传说明](资料文件上传说明.md)。不要再把历史 course-ds、kp-stack、q-stack-1 等静态值作为生产约定；联调应使用 B 创建后返回的真实 ID。教师题库与学生取题严格分离，学生作答阶段不能获取标准答案。

## A 对接 B 的测验流程

1. 教师登录，创建课程、章节和 active 知识点并发布课程。
2. 教师 POST `/teacher/courses/{course_id}/questions` 创建 active 题目。
3. POST 创建试卷，PUT 配题与分值，POST publish 冻结内容。
4. 学生登录并选课，GET `/courses/{course_id}/exams` 查询试卷。
5. POST `/exams/{exam_id}/attempts` 开始，GET `/attempts/{attempt_id}` 取得公共题目和已有答案。
6. PUT answers，提交选项 ID 与 revision；等待全部保存成功后 POST submit。
7. GET result 和课程 attempts 查看结果及历史。复测开始时传 baseline_attempt_id。

公共响应为 `{code:0,message:"ok",data:...,request_id:"..."}`，除健康和文档外均按当前权限携带 Bearer Token。422 表示参数错误，409 表示状态或版本冲突。完整路径、字段、错误码及联调示例见 [测验业务接口说明](测验业务接口说明.md)。

## D 可接收的数据

所属教师可 GET `/teacher/attempts/{attempt_id}/diagnosis-input`，提取响应 data：

```json
{
  "attempt_id":"真实作答ID",
  "course_id":"真实课程ID",
  "graded_answers":[
    {"question_id":"真实题目ID","knowledge_point_ids":["真实知识点ID"],"correct":false}
  ],
  "knowledge_points":[{"id":"真实知识点ID","name":"栈"}],
  "resource_catalog":[]
}
```

复测额外带 `baseline: {knowledge_points: [...]}`，项字段为 `knowledge_point_id,name,correct_count,sample_count,accuracy,status`。此旧格式不包含 evidence_question_ids 或标准答案，兼容 D 原有的 extra=forbid 校验。B 负责按标准答案确定性评分。

上述旧接口 resource_catalog 仍为空，以保持原契约。新 `/internal/attempts/{attempt_id}/diagnosis-input` 使用 D 独立服务密钥和课程白名单，包含冻结题干、选项、标准答案、最终作答、answered、得分、知识点统计、复测基准、真实当前版本 ready 的资料目录及 warnings。新数据不能直接传给旧 D 模型，需 D 新增适配。B 的基础知识点统计不等同于 D 的 AI 诊断报告。

## 下一步接入边界

| 成员 | 需要约定的输入/输出 |
| --- | --- |
| B 与 C | 资料 ID、所属课程、知识点、标题、文件/正文位置、版本、解析索引状态；上传/更新/删除后的索引同步，按 course_id 限定检索范围 |
| B 与 D | 已提交 attempt_id、上述诊断输入；诊断任务状态、版本、结果、失败重试和同一作答重复请求去重 |
| C 与 D | 检索 query、course_id、knowledge_point_ids、top_k；证据的文档/切片/资源 ID、内容、定位及来源 |
| A 与 B | 资料处理状态、测验结果、诊断任务进度、报告与来源链接 |

当前内部鉴权已实现 C_SERVICE_KEY、D_SERVICE_KEY 及各自课程白名单。B→D 的通知另使用 DIAGNOSIS_SERVICE_KEY，不把密钥交给浏览器。C/D 不直接访问 B 的数据库；字段、删除/版本保护和联调步骤以新内部接口和任务交付文档为准。自动创建通知任务、输入快照和投递重试已实现；D 接收端、诊断完成回调、报告保存和学生报告查询仍需接入。
