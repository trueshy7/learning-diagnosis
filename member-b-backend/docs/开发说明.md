```text

  models.py        用户、登录会话、测验记录
```

## 已能运行的业务

所有 `/api/v1` 成功响应为 `{code:0,message:"ok",data:...,request_id:...}`。错误同时返回相应 HTTP 状态与非零 `code`。健康检查 `/health` 单独返回状态。

| 方法及路径 | 功能 | 权限 |
| --- | --- | --- |
| POST `/api/v1/auth/login` | 用户名密码换取24小时访问令牌 | 无需登录 |
| POST `/api/v1/auth/logout` | 撤销当前令牌 | 已登录 |
| GET `/api/v1/courses` | 查询样例课程 | 已登录 |
| GET `/api/v1/courses/{id}/questions` | 返回题干选项，不含标准答案 | 已登录 |
| POST `/api/v1/attempts` | 完成整张样例试卷计分并请求D生成报告 | 已登录 |
| GET `/api/v1/attempts` | 查询本人历史记录 | 已登录 |
| GET `/api/v1/attempts/{id}` | 查询本人一次测验 | 记录本人 |
| POST `/api/v1/attempts/{id}/report` | 启动D后重新生成报告 | 记录本人 |
| GET `/api/v1/teacher/overview` | 样例统计概况 | 教师 |
| POST `/api/v1/teacher/resources` | 把课程文本交给C导入 | 教师 |

当前教师概况的资源数量来自静态目录；新导入资料尚未同步到业务资源表或推荐目录。课程与题库管理接口、真实资源目录持久化和学生列表后续实现，不应据此认为教师模块已完成。

## 评分与存储

当前样例固定包含六道题，每题一分。答案集合完全相等才正确，漏答为零；非法选项、重复题目被拒绝。一次提交会为整张试卷生成判分快照，未提交的题仍按未答处理。知识点诊断由D进行；B不重复实现诊断算法。

可选请求头 `Idempotency-Key` 在同一用户下标识一次提交。相同键与相同请求返回原记录，相同键但不同请求返回409。没有该头时每次提交创建新测验，前端接入时应在重试中保留同一个键。初始版尚需补充多进程并发提交的冲突恢复，不能把此实现视为完整分布式幂等方案。

成绩先提交数据库，再请求D；D失败不会回滚成绩。`report:null` 是有效的失败状态，A应显示分数及 `ai_message`。通过重新生成报告接口可以恢复；不会伪造成功结果。

复测请求可加 `baseline_attempt_id`，B检查其归属并向D传递前测知识点统计，D仅比较双方覆盖充分的同一知识点。

## 与其他成员的边界

A只调用本服务的业务接口。B向D发送作答快照、知识点目录及有效资源目录；D直接向C检索。C、D的内部HTTP接口当前仅用于本机开发，正式部署前需增加内部认证与可信网络配置。

共享样例标识：`course-ds`；知识点 `kp-stack`、`kp-queue`；资源 `res-stack`、`res-queue`。修改时与C/D同步，不按展示名称关联数据。

## 数据库与配置

默认数据库为 `data/demo.db`。`.env.example` 给出 MySQL URL 模板；切换前自行创建数据库和专用账号，再设置 `DATABASE_URL`。SQLite 路径不应提交到仓库，MySQL配置不得提交真实口令。

当前仅用 `create_all` 建初始表，未引入 Alembic；修改表结构时需要迁移脚本。MySQL配置入口已给出，交付前验证的是SQLite路径，并未连接真实MySQL。
