教师创建题目时必须填写本课程已有的知识点 ID。仅支持单选题，选项 ID 不可重复，正确答案必须指向其中一个选项。重复课程、知识点或题目 ID 返回 409；未知课程返回 404；无效题目和跨课程知识点返回 422。学生取题接口绝不返回 `correct_option_ids`，教师题库接口返回答案和启停状态；可用 `active`、`knowledge_point_id` 筛选。停用题目不再出现在新测验中，历史作答使用提交时保存的快照。教师概况的资源数量来自业务数据库，资料导入成功后才记录为 `indexed`。课程元数据编辑及学生列表留待下一阶段。

建课到测验的最短流程：

```json
POST /api/v1/teacher/courses
{"id":"course-algo","name":"算法基础","description":"排序与查找"}

POST /api/v1/teacher/courses/course-algo/knowledge-points
{"id":"kp-sort","name":"排序"}

POST /api/v1/teacher/courses/course-algo/questions
{"id":"q-sort-1","stem":"哪种排序稳定？","kind":"single","options":[{"id":"A","text":"归并排序"},{"id":"B","text":"快速排序"}],"correct_option_ids":["A"],"knowledge_point_ids":["kp-sort"]}
```

这三个 POST 需要教师令牌。学生随后通过对应课程取题、提交 `/api/v1/attempts` 即可计分。

## 评分与存储

演示课程初始包含六道题；新课程的题数由教师配置。每题一分，漏答为零；已提交的单选题必须且只能选择一个有效选项，非法选项、重复题目被拒绝。常规提交按该课程当前全部启用题目计分；提交 `question_ids` 时只按指定的启用题目计分，记录标记为 `kind=practice`。每次提交都保存当时的题干、选项、正确答案和本人作答快照，教师之后修改或停用题目不会改变历史成绩与复盘。没有可用题目的课程暂不能提交测验，返回 422。知识点诊断由D进行；B不重复实现诊断算法。

`GET /courses/{id}/practice` 可传 `knowledge_point_id` 和 `limit`，优先返回当前错题，再补其他启用题；返回 `question_ids` 与隐藏答案的 `questions`。将所选 `question_ids` 连同答案提交 `/attempts` 即可完成一次针对性练习。错题本按每道题最近一次提交结果判断；做对后会从当前错题本移出。旧版本创建的测验没有题目快照时，复盘返回 `snapshot_available=false`，但进度仍能使用原有判分记录。

可选请求头 `Idempotency-Key` 在同一用户下标识一次提交。相同键与相同请求返回原记录，相同键但不同请求返回409。没有该头时每次提交创建新测验，前端接入时应在重试中保留同一个键。初始版尚需补充多进程并发提交的冲突恢复，不能把此实现视为完整分布式幂等方案。

成绩先提交数据库，再请求D；D失败不会回滚成绩。`report:null` 是有效的失败状态，A应显示分数及 `ai_message`。通过重新生成报告接口可以恢复；不会伪造成功结果。

复测请求可加 `baseline_attempt_id`，B检查其归属及课程一致性并向D传递前测知识点统计，D仅比较双方覆盖充分的同一知识点。

## 与其他成员的边界

A只调用本服务的业务接口。B向D发送作答快照、知识点目录及有效资源目录；D直接向C检索。C、D的内部HTTP接口当前仅用于本机开发，正式部署前需增加内部认证与可信网络配置。

共享样例标识：`course-ds`；知识点 `kp-stack`、`kp-queue`；资源 `res-stack`、`res-queue`。修改时与C/D同步，不按展示名称关联数据。

## 数据库与配置

默认数据库为 `data/demo.db`。`.env.example` 给出 MySQL URL 模板；切换前自行创建数据库和专用账号，再设置 `DATABASE_URL`。SQLite 路径不应提交到仓库，MySQL配置不得提交真实口令。

当前仅用 `create_all` 建初始表，未引入 Alembic；修改现有表结构时需要迁移脚本。演示数据只在对应 ID 缺失时补入，不覆盖已有记录。MySQL配置入口已给出，交付前验证的是SQLite路径，并未连接真实MySQL。
