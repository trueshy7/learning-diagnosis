## 2. 公共约定

### 2.1 请求格式

JSON 请求使用 `Content-Type: application/json`；资料文件上传使用 multipart/form-data，knowledge_point_ids 支持单个 ID、重复同名字段、英文逗号分隔或 JSON 数组字符串，统一解析后仍校验 1～50 个不重复 ID。请求模型继承 StrictModel，配置 extra='forbid'；上传表单拒绝未定义字段，除知识点外不允许重复同名字段。缺失必填字段、类型或格式不符合要求、多余字段会返回 HTTP 422。

验证码是字符串，必须保留开头的零。不要将 `"082391"` 转成数字 `82391`。

当前没有实现请求幂等键，也没有跨所有接口的统一限流器。验证码发送间隔及错误次数均按“邮箱 + 用途”执行，注册和重置密码的计数相互独立。

### 2.2 成功响应

除健康检查和原文件二进制下载外，业务成功响应统一为：

```json
{
  "code": 0,
  "message": "ok",
  "data": {},
  "request_id": "eac8f623d24c43829e262d320fbfbb21"
}
```

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `code` | integer | 成功固定为 `0`，与 HTTP 201 等传输状态区分 |
| `message` | string | 成功固定为 `ok` |
| `data` | object | 各接口业务结果 |
| `request_id` | string | 服务端为本次请求生成的 UUID 十六进制文本 |

中间件还会将请求 ID 放在响应头 `X-Request-ID`。健康检查和框架文档响应也经过该中间件，但其响应体不一定包含 `request_id`。

### 2.3 业务错误

显式抛出的 HTTP 错误使用对应 HTTP 状态码，响应示例：

```json
{
  "code": 400,
  "message": "验证码不正确",
  "data": null,
  "request_id": "eac8f623d24c43829e262d320fbfbb21"
}
```

`code` 与 HTTP 错误状态一致。发送验证码被限频时还会有 `Retry-After` 响应头。未知路径产生的 404 也使用 HTTP 异常处理器。

### 2.4 输入校验错误

HTTP 422 响应示例：

```json
{
  "code": 422,
  "message": "请求参数不符合接口约定",
  "data": {
    "errors": [
      {
        "loc": ["body", "verification_code"],
        "msg": "String should have at least 6 characters",
        "type": "string_too_short"
      }
    ]
  },
  "request_id": "eac8f623d24c43829e262d320fbfbb21"
}
```

`loc` 表示错误字段位置；跨字段错误（例如两次密码不一致）的定位可能在整个 `body`。`msg` 可能来自 Pydantic 的英文默认消息或自定义中文消息，客户端应结合状态和字段位置处理，不要依赖某条默认英文消息固定不变。返回的错误列表只包含 `loc`、`msg`、`type`，不回显原始输入。

未捕获的运行时异常可能返回 HTTP 500，并不保证具有上述业务响应格式。登录、退出、鉴权、注册和重置密码的 SQLAlchemy 数据库异常会转换为 HTTP 503，不向响应暴露数据库原始错误。

### 2.5 鉴权

登录成功后保存原始 `access_token`，调用受保护接口时携带：

```http
Authorization: Bearer <access_token>
```

服务端不使用 JWT，而是将 Token 计算为 SHA-256 摘要，查询 `login_sessions` 并检查过期时间及用户是否存在。会话到期或被撤销后须重新登录；访问不会自动续期。

| HTTP 状态 | 鉴权消息 | 原因 |
| --- | --- | --- |
| 401 | `请先登录` | 没有可识别的 Bearer 凭据 |
| 401 | `登录状态已失效` | 会话不存在或 `expires_at <= now` |
| 401 | `用户不存在` | 会话存在但关联用户不存在 |
| 503 | `登录凭证验证服务暂不可用，请稍后重试` | 查询登录会话或关联用户时数据库发生故障 |

教师课程接口使用教师权限依赖，学生访问返回 `403 需要教师权限`；学生的“我的课程”和选退课接口使用学生权限依赖，教师访问返回 `403 需要学生权限`。此外，教师管理操作还会按当前用户 ID 校验课程归属，越权或不存在统一返回 404。

## 3. POST /user/send-register-code

### 3.1 功能与请求

生成六位数字注册验证码，通过 SMTP 发送到指定邮箱。不要求登录，不要求邮箱已经存在于用户表，也不会在本接口检查邮箱是否已注册。

| 字段 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- |
| `email` | string | 是 | 普通 ASCII 邮箱，规范化后总长不超过 255 |

邮箱规范化与校验由 `app/email_utils.py` 统一处理：

- 去除首尾空白，整个地址转为小写，包括本地部分。
- 必须恰好包含一个 `@`，本地部分长度 1～64。
- 本地部分仅允许代码中规定的 ASCII 字母、数字及常见特殊字符；不能以点开头或结尾，也不能出现连续点。
- 域名至少包含两段；每段长度 1～63，允许 ASCII 字母、数字及中间的连字符，不允许首尾连字符。
- 不支持邮箱显示名称、带引号的本地部分或直接输入中文邮箱地址；不做 DNS 或邮箱存在性查询。

```json
{"email": "student@example.com"}
```

### 3.2 成功响应

HTTP 200：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "sent": true,
    "email": "student@example.com",
    "expires_in": 300,
    "retry_after": 60
  },
  "request_id": "eac8f623d24c43829e262d320fbfbb21"
}
```

| `data` 字段 | 类型 | 含义 |
| --- | --- | --- |
| `sent` | boolean | SMTP 服务接受邮件且数据库提交成功时为 `true` |
| `email` | string | 规范化后的收件邮箱 |
| `expires_in` | integer | 配置的验证码有效期，当前 300 秒 |
| `retry_after` | integer | 配置的重新发送间隔，当前 60 秒 |

有效期和发送间隔从服务器生成验证码时计算，不是从客户端收到响应时重新计算。`sent` 不保证邮件一定进入收件箱。原始验证码及其摘要均不在响应中返回。

### 3.3 处理流程

1. 校验请求字段和 SMTP 配置，校验摘要密钥配置。
2. 生成验证码和绑定邮箱、`register` 用途的 HMAC 摘要。
3. 锁定该邮箱的验证码记录，检查 60 秒冷却时间。
4. 替换旧摘要，设置 300 秒有效期，错误次数归零，使用时间清空。
5. 同步发送邮件，成功后提交数据库事务并返回。

重发成功后旧验证码失效。SMTP 失败时回滚本次更新，不会消费旧验证码；此时旧验证码本身仍须满足原有效期等条件。SMTP 已发送但数据库提交失败时，邮件中的新验证码不能保证有效，应重新获取。

### 3.4 错误

| HTTP 状态 | `message` | 条件 |
| --- | --- | --- |
| 422 | `请求参数不符合接口约定` | 邮箱缺失、类型或格式不正确、存在额外字段 |
| 429 | `请在 N 秒后重新获取验证码` | 同一邮箱距上次生成不足 60 秒；响应头 `Retry-After: N` |
| 503 | `验证码邮件服务尚未配置完成` | SMTP 配置或验证码摘要密钥不满足要求 |
| 502 | `邮件发送失败，请稍后重试` | SMTP 连接、认证、发送、收件人拒绝或网络错误 |
| 503 | `验证码服务暂不可用，请稍后重试` | 数据库操作失败 |

### 3.5 调用示例

```sh
curl -X POST http://127.0.0.1:8000/user/send-register-code \
  -H 'Content-Type: application/json' \
  -d '{"email":"student@example.com"}'
```

## 4. POST /user/register

### 4.1 功能与请求

校验邮箱验证码并创建账号，注册时可选择学生或教师角色。不要求登录，成功后不自动登录。

| 字段 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- |
| `username` | string | 是 | 去除首尾空白后 3～64 字符，匹配 `^[\w-]+$`，允许中文等 Unicode 单词字符、下划线和连字符 |
| `role` | string | 否 | 仅允许 `student`（学生）或 `teacher`（教师）；不传默认 `student`，区分大小写，不能为 `null` |
| `email` | string | 是 | 与发送验证码接口相同的规范化和校验规则，必须使用收到验证码的邮箱 |
| `password` | string | 是 | 8～128 字符，至少一个 ASCII 英文字母和一个 ASCII 数字，不能有不可打印字符 |
| `confirm_password` | string | 是 | 8～128 字符，必须与 `password` 完全一致 |
| `verification_code` | string | 是 | 六位 ASCII 数字，必须保留前导零 |

密码不会被 `strip()` 或转为小写；其中的普通空格会保留。长度按字符而不是 UTF-8 字节数计算。当前不要求同时包含大小写或特殊符号。请求不接受 `id`、`password_hash` 等额外字段。角色按校验通过的 `role` 保存；`admin`、空字符串、`Teacher` 等值返回 422，且不会消费邮箱验证码。

```json
{
  "username": "student01",
  "email": "student@example.com",
  "role": "student",
  "password": "Example123!",
  "confirm_password": "Example123!",
  "verification_code": "082391"
}
```

### 4.2 成功响应

HTTP 201，业务 `code` 仍为 0：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "id": 42,
    "username": "student01",
    "email": "student@example.com",
    "role": "student"
  },
  "request_id": "eac8f623d24c43829e262d320fbfbb21"
}
```

`id` 为自增用户 ID，`username`、`email` 为规范化后存储的值，`role` 为实际保存的所选角色。教师注册时将请求中的 `role` 改为 `teacher`，成功响应、后续登录及 `/user/info` 均返回 `teacher`。不传角色的旧请求继续创建学生账号。不会返回密码、确认密码、密码哈希、验证码或访问令牌。

### 4.3 验证码与事务流程

1. 输入校验通过后，使用注册邮箱和 `register` 用途计算验证码摘要。
2. `SELECT ... FOR UPDATE` 锁定该邮箱的注册验证码记录。
3. 先检查记录存在、未过期且未使用，再检查次数是否小于 5。
4. 使用 `hmac.compare_digest` 比较摘要；不正确则增加错误次数并提交。
5. 摘要正确后检查用户名或邮箱是否重复。
6. 为密码生成随机盐和 PBKDF2-HMAC-SHA256 哈希，按校验后的角色创建用户。
7. 在同一个事务中标记验证码 `used_at` 并创建用户；提交成功后才返回成功。

第 1～4 次错误返回 400；第 5 次错误及之后对该未过期验证码的尝试返回 429，即使后来输入正确也必须重新获取。格式不合法的请求不会增加错误次数。账号重复不会消费验证码。数据库唯一约束也会处理并发注册中的重复账号冲突。

验证码已使用或已过期时优先返回 400。注册与验证码消费提交失败会一起回滚；错误验证码的尝试次数则已经单独提交，不随业务拒绝撤销。

### 4.4 错误

| HTTP 状态 | `message` | 条件 |
| --- | --- | --- |
| 422 | `请求参数不符合接口约定` | 字段缺失、格式或长度不合理、密码不一致、多余字段 |
| 400 | `验证码无效或已过期，请重新获取` | 未获取验证码、已过期或已使用 |
| 400 | `验证码不正确` | 摘要错误，累计次数尚未达到 5 |
| 429 | `验证码错误次数过多，请重新获取` | 本次达到或此前已达到 5 次错误 |
| 409 | `用户名或邮箱已被注册` | 账号重复或 MySQL 并发唯一键冲突 |
| 503 | `验证码服务尚未配置完成` | 验证码密钥未配置或不足 32 字节 |
| 503 | `注册服务暂不可用，请稍后重试` | 数据库查询、写入或提交失败 |

注册错误次数达到上限的 429 不携带 `Retry-After`；需要重新发码，而不是只等待后继续尝试旧码。重复发送验证码接口的 429 则携带该响应头。

### 4.5 调用示例

将 `verification_code` 替换为实际邮件收到的值：

```sh
curl -X POST http://127.0.0.1:8000/user/register \
  -H 'Content-Type: application/json' \
  -d '{"username":"student01","email":"student@example.com","role":"student","password":"Example123!","confirm_password":"Example123!","verification_code":"082391"}'
```

## 5. POST /user/login

源码中仍有旧 `/auth/login` 路由定义，但当前 `main.py` 未挂载 `auth.router`，访问旧路径返回 404；应使用 `/user/login`。

### 5.1 功能与请求

使用用户名和密码登录；不支持用邮箱替代用户名。请求使用 JSON，不是 OAuth2 表单。

| 字段 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- |
| `username` | string | 是 | 去除首尾空白后长度 3～64，匹配 `^[\w-]+$`；不转为小写 |
| `password` | string | 是 | 长度 8～128；与存储哈希校验，不重复执行注册时的字母、数字组合规则 |

```json
{"username": "student01", "password": "Example123!"}
```

登录用户名匹配的大小写行为还受 MySQL 排序规则影响。密码不做去空白或大小写转换，需与注册或重置时设置的原始密码一致。没有验证码字段；提交多余的图片验证码或邮箱验证码字段会返回 422。

### 5.2 成功响应

HTTP 200：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "access_token": "example-random-token",
    "token_type": "bearer",
    "user": {"id": 42, "username": "student01", "role": "student"}
  },
  "request_id": "eac8f623d24c43829e262d320fbfbb21"
}
```

| `data` 字段 | 类型 | 含义 |
| --- | --- | --- |
| `access_token` | string | 客户端后续使用的原始随机 Token |
| `token_type` | string | 固定为 `bearer` |
| `user.id` | integer | 用户 ID |
| `user.username` | string | 用户名 |
| `user.role` | string | 用户角色 |

每次登录创建新会话，有效期 86400 秒；其他有效会话不会自动失效。响应当前没有 `expires_in`、刷新令牌或邮箱字段。数据库只保存 Token 的 SHA-256 摘要。

登录校验时对用户行加锁，与密码重置串行化：若重置先提交，后续登录必须使用新密码；若旧密码登录先完成，其会话会被随后完成的重置删除。登录成功返回前提交会话事务。

成功登录时会清理数据库中所有已到期会话，不只是当前用户的会话。未成功登录不会执行该清理。

### 5.3 错误与示例

| HTTP 状态 | `message` | 条件 |
| --- | --- | --- |
| 422 | `请求参数不符合接口约定` | 缺失字段、长度不符合要求或额外字段 |
| 401 | `用户名或密码错误` | 用户不存在或密码校验不通过 |
| 503 | `登录服务暂不可用，请稍后重试` | 查询、创建会话或提交数据库失败 |

```sh
curl -X POST http://127.0.0.1:8000/user/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"student01","password":"Example123!"}'
```

## 6. POST /user/exit

源码中仍有旧 `/auth/logout` 路由定义，但当前未挂载，访问返回 404；应使用 `/user/exit`。

### 6.1 功能与请求

撤销当前 Bearer Token。需要有效会话，使用必需的 `Authorization` 请求头，没有定义请求体。

```sh
curl -X POST http://127.0.0.1:8000/user/exit \
  -H 'Authorization: Bearer <登录返回的access_token>'
```

先完成鉴权，再按当前 Token 摘要删除会话并提交。只影响当前会话，不会删除用户，也不会让其他设备的 Token 失效。

### 6.2 成功响应

HTTP 200：

```json
{
  "code": 0,
  "message": "ok",
  "data": {"logged_out": true},
  "request_id": "eac8f623d24c43829e262d320fbfbb21"
}
```

### 6.3 错误与重复调用

无有效 Bearer 凭据、会话不存在、已过期或关联用户不存在时，按公共鉴权约定返回 401。请求参数校验错误按 FastAPI 校验规则返回 422。

鉴权过程中数据库故障返回公共鉴权 503；鉴权通过后，删除会话或提交失败返回 `503 退出服务暂不可用，请稍后重试`。

成功退出后，同一个 Token 再次调用本接口通常返回 `401 登录状态已失效`，不会再次返回成功。因此调用方应清除本地 Token，而不是依赖重复退出成功。

## 7. GET /user/info

验证 `Authorization: Bearer <access_token>` 后返回当前登录用户的信息，不接收请求体，不通过客户端提交的用户 ID 选择其他用户。

```sh
curl http://127.0.0.1:8000/user/info \
  -H 'Authorization: Bearer <登录返回的access_token>'
```

HTTP 200，使用公共成功包装，`data` 为：

```json
{"username": "student01", "role": "student", "email": "student@example.com"}
```

三个字段均为字符串。角色来自数据库，不会根据请求参数修改；响应不包含密码、密码哈希、Token 或其他账号的信息。鉴权失败返回公共 401；鉴权数据库故障返回公共 503。

## 8. POST /user/send-reset-password-code

### 8.1 请求与用途

找回密码的第一步，向**已注册邮箱**发送重置验证码，无需先登录。字段规则与注册发码接口相同，仅接受邮箱，不需要图片验证码或旧密码。

```json
{"email": "student@example.com"}
```

代码先检查邮箱格式，再查询账号是否存在。邮箱存在后才检查 SMTP 配置并发送邮件。未注册邮箱返回 404，不发送邮件。邮件主题与正文明确标记“重置密码”。

```sh
curl -X POST http://127.0.0.1:8000/user/send-reset-password-code \
  -H 'Content-Type: application/json' \
  -d '{"email":"student@example.com"}'
```

### 8.2 成功响应及状态

HTTP 200，使用公共成功包装，`data` 为：

```json
{"sent": true, "email": "student@example.com", "expires_in": 300, "retry_after": 60}
```

重置验证码为六位数字字符串，5 分钟有效，同一邮箱、同一用途 60 秒内不可重复发送。用途固定为 `reset_password`，与注册用途 `register` 独立；重置发码不会替换或消费注册验证码。重置发码本身不修改密码，也不撤销现有会话。

### 8.3 错误

| HTTP 状态 | `message` | 条件 |
| --- | --- | --- |
| 422 | `请求参数不符合接口约定` | 邮箱格式、类型、必填或额外字段不符合要求 |
| 404 | `该邮箱尚未注册` | 查询不到对应账号，不发送邮件 |
| 429 | `请在 N 秒后重新获取验证码` | 重置用途发送间隔不足 60 秒，附 `Retry-After: N` |
| 503 | `验证码邮件服务尚未配置完成` | SMTP 或验证码密钥配置不正确 |
| 502 | `邮件发送失败，请稍后重试` | SMTP 或网络发送失败 |
| 503 | `验证码服务暂不可用，请稍后重试` | 数据库查询、写入或提交失败 |

邮件发送失败会回滚本次摘要更新；邮件发送与数据库提交的边界与注册发码接口相同。响应不包含验证码或摘要。

## 9. POST /user/resetPassword

### 9.1 请求

找回密码的第二步，收到重置邮件验证码后提交两次新密码，无需登录，不要求旧密码。这个接口不负责发送邮件，应先调用上一节发码接口。

| 字段 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- |
| `email` | string | 是 | 与重置发码时相同的邮箱，按公共规则规范化和校验 |
| `verification_code` | string | 是 | 邮箱收到的六位重置验证码，必须保留前导零 |
| `password` | string | 是 | **新密码**，8～128 字符，至少一个 ASCII 英文字母和一个 ASCII 数字，不能包含不可打印字符 |
| `confirm_password` | string | 是 | 第二次输入的新密码，须完全一致 |

密码空格不会去除。字段名称为 `password`、`confirm_password`，不是 `old_password`、`new_password`，不接受额外字段。

```json
{
  "email": "student@example.com",
  "verification_code": "082391",
  "password": "NewPassword456!",
  "confirm_password": "NewPassword456!"
}
```

### 9.2 成功与事务

HTTP 200，使用公共成功包装，`data` 为：

```json
{"password_reset": true}
```

处理顺序：

1. 校验邮箱、新密码强度、两次新密码一致性及验证码格式。
2. 锁定该邮箱 `reset_password` 验证码行，检查未过期、未使用、错误次数小于 5，再比较摘要。
3. 验证码通过后，锁定对应用户行，确认账号仍存在。
4. 生成新随机盐及密码哈希，覆盖 `password_hash`，不保存新密码明文。
5. 标记本次验证码已使用，删除该用户**所有** `login_sessions`。
6. 更新密码、消费验证码和删除会话一起提交；数据库失败则一起回滚。

成功后旧密码不可再登录，所有设备的旧 Token 失效，需使用新密码调用 `/user/login`。其他用户的会话不受影响，用户角色和邮箱不变。验证码只能成功使用一次。错误次数的持久化规则与注册一致：第 1～4 次错误返回 400，第 5 次及之后返回 429，重新获取重置验证码才能恢复尝试。

### 9.3 错误

| HTTP 状态 | `message` | 条件 |
| --- | --- | --- |
| 422 | `请求参数不符合接口约定` | 邮箱、验证码或密码格式不合法、两次密码不一致、额外字段 |
| 400 | `验证码无效或已过期，请重新获取` | 没有该邮箱的重置验证码、已过期或已使用；只有注册码也不满足条件 |
| 400 | `验证码不正确` | 重置验证码摘要不匹配，未达到 5 次错误 |
| 429 | `验证码错误次数过多，请重新获取` | 错误次数达到上限，无 `Retry-After`，需重新发码 |
| 404 | `该邮箱尚未注册` | 验证码有效，但账号已不存在，例如发码后账号被删除 |
| 503 | `验证码服务尚未配置完成` | 验证码摘要密钥未配置或长度不足 |
| 503 | `重置密码服务暂不可用，请稍后重试` | 数据库查询、更新密码、删除会话或提交失败 |

```sh
curl -X POST http://127.0.0.1:8000/user/resetPassword \
  -H 'Content-Type: application/json' \
  -d '{"email":"student@example.com","verification_code":"082391","password":"NewPassword456!","confirm_password":"NewPassword456!"}'
```

| `SMTP_PASSWORD` | 默认空，发信必填 | SMTP 密码或服务商授权码 |

| `DIAGNOSIS_TIMEOUT` / `DIAGNOSIS_MAX_ATTEMPTS` | 默认 10 秒 / 5 次，范围见任务文档 | 通知超时、租约及自动重试上限 |

程序实际加载的是根目录 `.env`，不会自动加载 `.env.example`。可在项目根目录运行 `python -m app.check_mail --config-only` 检查配置，再运行 `python -m app.check_mail` 检查 SMTP 加密连接和账号认证。自检不发送邮件，也不会输出 SMTP 密码或验证码密钥；实际投递需通过发送验证码接口验证。

## 12. 建议的联调顺序

1. 配置 MySQL、SMTP 和 `EMAIL_VERIFICATION_SECRET`，启动服务。
2. 调用 `/health` 确认应用可响应，访问 `/docs` 查看请求模型。
3. 调用 `/user/send-register-code`，在邮箱中取得真实验证码。
4. 调用 `/user/register`，确认返回 201 和用户 ID。
5. 调用 `/user/login` 获取 `access_token`。
6. 带 Bearer Token 调用 `/user/info`，核对用户名、角色和邮箱。
7. 带同一 Token 调用 `/user/exit`，再用旧 Token 获取信息，应返回 401。
8. 再次登录，调用 `/user/send-reset-password-code`，收到重置验证码后调用 `/user/resetPassword`。
9. 确认此前所有 Token 失效，旧密码登录返回 401，新密码可登录，重置验证码不可重复使用。

接口示例和业务分支按源代码整理；默认自动化回归使用数据库、SMTP 替身，不等于完成真实邮件投递或真实 MySQL 并发事务验证。新增真实 MySQL 测验测试需显式设置 TEST_MYSQL_URL，执行方式及临时库权限见测验文档。OpenAPI 自动列出请求模型和基础响应，不会自动列全代码中显式抛出的业务状态；错误行为以上文、测验文档和路由实现为准。
