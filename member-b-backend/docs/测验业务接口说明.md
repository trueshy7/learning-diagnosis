# 测验业务接口说明

当前实现采用“教师维护客观题库 → 发布固定试卷 → 学生限时作答 → 确定性评分 → 知识点统计 → 导出诊断输入”的流程。全部数据来自 MySQL，不使用静态样例题库。模型字段见 [测验数据模型说明](测验数据模型说明.md)，认证与响应约定见 [接口详细说明](接口详细说明.md)。

## 1. 业务规则

- 教师只能维护自己课程的题目、试卷，查看自己课程的成绩。已归档课程不能维护题库或修改、发布试卷；仍能查询记录和归档试卷。
- 第一阶段支持单选 `single`、多选 `multiple`。每题恰好关联一个当前课程的 active 知识点，便于统计错误归属；数据库关联表保留以后支持多知识点的能力。
- 单选恰好一个正确选项，多选至少两个正确选项。选项 2～10 个，标签从 A～J 中选择且不能重复。
- 题目采用 `draft / active / disabled` 状态；只有 active 题能组卷和发布。删除接口实际停用题目，保留历史引用。
- 试卷采用 `draft → published → archived` 状态，也允许草稿直接归档。发布前课程必须是 published，试卷必须有 1～100 道同课程 active 题。
- 发布时冻结题干、选项 ID、正确答案、教师解析、题目知识点及课程有效知识点目录。此后编辑、停用原题不会改变已发布试卷或历史成绩；发布后不能改标题、时长、题目、分值，归档后不能恢复。
- 只有 active 选课且课程、试卷均 published 的学生能首次开始。每个学生每份试卷只保留一次正式作答，重复开始返回同一记录。复测通过另一份试卷关联已完成的同课程作答。
- 已开始记录不因退课、课程归档或试卷归档而失效，仍可在截止前作答、提交和查询自己的历史；归档只阻止新的开始。
- 单题完全匹配标准答案得全分，多选漏选、多选、错选及未答均为零，无部分分。使用 Decimal 计算，最多保留两位小数，结果 JSON 返回数字。
- 时限由服务器控制，`server_time >= expires_at` 即超时，只按最后成功保存的答案结算。前端倒计时仅作展示。
- 学生作答接口不返回标准答案或解析；结束后的结果接口才返回。教师详情接口包含标准答案，禁止前端作为学生取题接口使用。

## 2. 公共约定

基础地址默认 `http://127.0.0.1:8000`，没有 `/api/v1` 前缀。以下所有接口需要：

```http
Authorization: Bearer <登录返回的 access_token>
Content-Type: application/json
```

成功统一 `{ "code": 0, "message": "ok", "data": ..., "request_id": "..." }`。下文响应示例只展示 `data`。请求不接受未定义字段，客户端不能指定教师、学生身份、成绩、总分或试卷快照。

分页参数通用：`page=1`（≥1）、`page_size=20`（1～100）。分页返回 `{items: [], total: 0, page: 1, page_size: 20}`。ID 均使用接口实际返回值，示例中的 `course_id / kp1 / q1 / exam_id / attempt_id` 只是占位值。

## 3. 教师题库接口（5 个）

| 方法 | 路径 | 成功状态 | 说明 |
| --- | --- | --- | --- |
| POST | `/teacher/courses/{course_id}/questions` | 201 | 创建题目 |
| GET | `/teacher/courses/{course_id}/questions` | 200 | 分页题库 |
| GET | `/teacher/questions/{question_id}` | 200 | 题目完整详情 |
| PUT | `/teacher/questions/{question_id}` | 200 | 完整替换题目内容 |
| DELETE | `/teacher/questions/{question_id}` | 200 | 停用题目 |

### 3.1 创建与完整修改

POST 和 PUT 使用相同请求格式：

```json
{
  "kind": "single",
  "stem": "栈的访问原则是什么？",
  "explanation": "栈遵循后进先出原则。",
  "status": "active",
  "knowledge_point_ids": ["kp1"],
  "options": [
    {"label": "A", "text": "后进先出", "is_correct": true},
    {"label": "B", "text": "先进先出", "is_correct": false}
  ]
}
```

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| `kind` | 是 | `single` 或 `multiple` |
| `stem` | 是 | 去首尾空白，1～10000 字符 |
| `explanation` | 否 | 可为 null，最多 10000 字符；教师提供的解析 |
| `status` | 否 | 默认 draft，可取 draft、active、disabled |
| `knowledge_point_ids` | 是 | 恰好一个 ID，长度 1～64；必须为本课程 active 知识点 |
| `options` | 是 | 2～10 项，数组顺序决定展示顺序 |
| `options[].label` | 是 | A～J，不能重复，不要求连续 |
| `options[].text` | 是 | 去首尾空白，1～2000 字符 |
| `options[].is_correct` | 是 | 严格 JSON 布尔值 true/false |

响应包含 `id, course_id, kind, stem, explanation, status, created_at, updated_at, knowledge_point_ids, knowledge_points, options`。`knowledge_points` 每项为 `{id,name,status}`，`options` 每项为 `{id,label,text,is_correct}`。

PUT 是完整替换：`status` 省略会使用 draft，`explanation` 省略会清空；选项生成新的 ID。因此修改后应重新读取题目，不能继续使用旧选项 ID。已发布试卷保留原选项快照，不受替换影响。

DELETE 返回 `{"id":"q1","status":"disabled"}`，重复停用返回同样状态。在未归档课程中，可通过 PUT 恢复 active。草稿试卷引用的题目被停用后，必须替换或重新启用才能发布。

### 3.2 题库列表与详情

列表可选查询参数：`status`、`kind`、`knowledge_point_id`、`keyword`（题干子串，最多 100 字符），并支持通用分页。按创建时间倒序、ID 升序排列。items 为摘要，字段 `id, course_id, kind, stem, status, created_at, updated_at`，不包含选项和解析。取完整题目调用教师详情接口。

## 4. 教师试卷接口（7 个）

| 方法 | 路径 | 成功状态 | 说明 |
| --- | --- | --- | --- |
| POST | `/teacher/courses/{course_id}/exams` | 201 | 创建草稿试卷 |
| GET | `/teacher/courses/{course_id}/exams` | 200 | 自己课程的试卷列表 |
| GET | `/teacher/exams/{exam_id}` | 200 | 试卷和题目详情，含答案 |
| PUT | `/teacher/exams/{exam_id}` | 200 | 完整更新草稿基础信息 |
| PUT | `/teacher/exams/{exam_id}/questions` | 200 | 完整替换草稿试卷题目及分值 |
| POST | `/teacher/exams/{exam_id}/publish` | 200 | 检查并发布、冻结快照 |
| POST | `/teacher/exams/{exam_id}/archive` | 200 | 归档，停止新的开始 |

### 4.1 创建与修改基础信息

```json
{"title":"数据结构初测","duration_seconds":1800}
```

`title` 去首尾空白后 1～100 字符；`duration_seconds` 为严格整数，60～14400 秒，省略默认 1800。PUT 同样使用完整请求，省略时长会恢复 1800。

试卷摘要响应：

```json
{
  "id":"exam_id", "course_id":"course_id", "title":"数据结构初测",
  "status":"draft", "duration_seconds":1800,
  "question_count":0, "total_score":0,
  "created_at":1800000000, "updated_at":1800000000
}
```

新试卷不自动选题。教师列表支持通用分页及可选 `status=draft|published|archived`，响应额外包含 `course_status`。详情在摘要基础上增加 `questions`：每项为完整题目快照以及 `score, sort_order`。草稿详情反映题库当前内容，发布后反映发布快照。

### 4.2 设置试卷题目

```json
{
  "questions":[
    {"question_id":"q1","score":"2.50"},
    {"question_id":"q2","score":5}
  ]
}
```

题目 1～100 道，不允许重复，同课程且 active。每题分值 >0 且 ≤1000，最多两位小数，可用数字或十进制字符串。数组顺序决定 `sort_order`（从 0 开始）。请求会整体替换旧配置，自动更新 `question_count` 和 `total_score`，返回试卷摘要。不能提交空数组；新建草稿可先保持无题状态。

### 4.3 发布与归档

两者都不需要请求体。发布会再次检查课程状态、题目状态、选项答案和知识点，防止组卷后题目被改坏。重复发布 published 试卷在课程未归档时返回原摘要，不会重建快照。归档返回 archived 摘要，重复归档允许；已开始作答不受影响。所有题库和试卷物理删除均不对外开放。

## 5. 学生测验接口（7 个）

| 方法 | 路径 | 成功状态 | 说明 |
| --- | --- | --- | --- |
| GET | `/courses/{course_id}/exams` | 200 | 所选课程的 published 试卷列表 |
| GET | `/courses/{course_id}/attempts` | 200 | 本人在此课程的作答历史 |
| POST | `/exams/{exam_id}/attempts` | 200 | 首次开始或获取已有作答 |
| GET | `/attempts/{attempt_id}` | 200 | 作答题目、已保存答案及版本 |
| PUT | `/attempts/{attempt_id}/answers` | 200 | 批量保存答案 |
| POST | `/attempts/{attempt_id}/submit` | 200 | 提交、评分并返回结果 |
| GET | `/attempts/{attempt_id}/result` | 200 | 查询已结束测验结果 |

### 5.1 查询与开始

学生试卷列表需要 active 选课且课程不是 draft，支持通用分页，返回摘要及 `course_status`。已归档课程仍可查看其 published 试卷摘要，但不能首次开始。试卷列表不包含题干和答案，归档试卷通过本人历史记录访问。

开始接口可不传请求体，也可传 `{}`；复测可传：

```json
{"baseline_attempt_id":"本人初测的作答ID"}
```

基准必须为本人同课程另一份试卷的 submitted/expired 记录；仍为 in_progress 时拒绝，可先查询其结果触发到期结算。基准一经开始不能修改。多次请求返回已有作答，即使已经结束，也不会重新计时或新建一份。

开始、历史 items、成绩列表 items 通用作答摘要：

```json
{
  "id":"attempt_id", "exam_id":"exam_id", "course_id":"course_id", "student_id":1,
  "baseline_attempt_id":null, "status":"in_progress",
  "started_at":1800000000, "expires_at":1800001800, "submitted_at":null,
  "score":null, "total_score":7.5, "server_time":1800000000
}
```

时间单位均为 Unix 秒。历史查询只返回本人记录，不要求当前仍选课，按 started_at 倒序、ID 升序。某课程没有本人记录时返回空列表。

### 5.2 获取作答详情

响应在作答摘要上增加 `questions` 和 `answers`：

```json
{
  "questions":[{
    "id":"q1", "kind":"single", "stem":"栈的访问原则是什么？",
    "options":[{"id":"opt1","label":"A","text":"后进先出"},
               {"id":"opt2","label":"B","text":"先进先出"}],
    "knowledge_point_ids":["kp1"], "score":2.5, "sort_order":0
  }],
  "answers":[{"question_id":"q1","selected_option_ids":[],"revision":0}]
}
```

此处仅展示增量字段。初始每题都有一行空答案，revision=0。页面刷新后从此接口恢复选择和版本。即使已结束，该接口也不包含标准答案，查看解析使用 result。

### 5.3 批量保存与版本冲突

```json
{
  "answers":[
    {"question_id":"q1","selected_option_ids":["opt1"],"revision":0},
    {"question_id":"q2","selected_option_ids":[],"revision":1}
  ]
}
```

每批 1～100 题，只更新这批题；题目不得重复，选项必须来自这份试卷快照对应题目，最多 10 个且不得重复。单选最多选一个，空数组用于清空答案。**提交的是 option.id，不是 A/B 标签，也不是索引。**

`revision` 为客户端最后读取的版本，非负严格整数。整批先校验再保存，任一版本不匹配返回 409，整批不写入。成功的每题 revision 加一，响应为：

```json
{"attempt_id":"attempt_id","answers":[
  {"question_id":"q1","selected_option_ids":["opt1"],"revision":1},
  {"question_id":"q2","selected_option_ids":[],"revision":2}
]}
```

前端应按题目串行保存、使用新版本；网络超时不能假定保存失败，先 GET 详情对齐服务端再重试。409 版本冲突同样重新读取详情，不应自动覆盖另一个页面的答案。

### 5.4 提交与结果

提交无请求体，只对**此前保存成功**的答案评分。前端必须等待所有保存请求成功，再调用 submit。不能将最后一批答案直接放进提交接口代替保存。

正常提交变为 submitted；已到期变为 expired。重复 submit 返回原有评分，不会重复累计或修改成绩。result 在尚未结束且未到期时返回 409。

结果在作答摘要上增加：

- `percentage`：得分 / 总分 ×100，四舍五入到两位小数。
- `questions`：作答时的公共题目字段，加 `selected_option_ids, correct_option_ids, correct, earned_score, explanation`。
- `knowledge_points`：发布时有效知识点的统计，包括没有被试卷覆盖的知识点。
- `comparison`：复测与基准中双方均至少 3 题的共同知识点正确率对比，无基准或样本不足时为空数组。

知识点统计示例：

```json
{
  "knowledge_point_id":"kp1", "name":"栈",
  "sample_count":3, "correct_count":2, "accuracy":0.666667,
  "status":"needs_practice", "evidence_question_ids":["q1","q2","q3"]
}
```

| 条件 | status | 含义 |
| --- | --- | --- |
| sample_count < 3 | `insufficient_evidence` | 样本不足，暂不推断掌握情况 |
| sample_count ≥3 且 accuracy <0.6 | `weak` | 本次测验表现薄弱 |
| sample_count ≥3 且 0.6≤accuracy<0.8 | `needs_practice` | 仍需练习 |
| sample_count ≥3 且 accuracy≥0.8 | `mastered` | 本次测验表现较好 |

未覆盖知识点 `sample_count=0, correct_count=0, accuracy=null`；不能把 null 显示成 0% 或判作薄弱。该统计是基于题量的基础规则，不是经过校准的能力估计，也不等于多智能体诊断报告。正确率不按分值加权；总分按题目分值计算。

复测 comparison 每项：`{knowledge_point_id, before_accuracy, after_accuracy, delta}`，delta 为正确率差，范围 -1～1。不同试卷的变化仅作学习反馈，不能据此认定因果或严格等值。

## 6. 教师成绩与诊断输入（3 个）

| 方法 | 路径 | 功能 |
| --- | --- | --- |
| GET | `/teacher/exams/{exam_id}/results` | 分页作答摘要，可用 student_id（正整数）筛选 |
| GET | `/teacher/attempts/{attempt_id}/result` | 完整单人成绩，响应同学生 result |
| GET | `/teacher/attempts/{attempt_id}/diagnosis-input` | 导出 D 的诊断请求 data |

均仅限课程所属教师。成绩列表包含进行中记录，其 score 为 null；单人结果及诊断导出在未结束时返回 409。列表与详情会对访问到的超时记录结算。

诊断输入示例：

```json
{
  "attempt_id":"attempt_id", "course_id":"course_id",
  "graded_answers":[{"question_id":"q1","knowledge_point_ids":["kp1"],"correct":true}],
  "knowledge_points":[{"id":"kp1","name":"栈"}],
  "resource_catalog":[]
}
```

复测额外包含 `baseline: {knowledge_points: [...]}`，基准项只含 `knowledge_point_id, name, correct_count, sample_count, accuracy, status`，与 D 当前严格请求模型兼容。导出不包含标准答案、学生选项或教师解析；外层 B 的响应包装不能直接传给 D，应提取 data。

此旧教师接口为兼容 D 原有严格模型，保留最小字段和空 resource_catalog。新增 `/internal/attempts/{attempt_id}/diagnosis-input` 供 D 临时导出完整数据。正式任务由测验结算同事务入队，独立 worker 向 D 交付 ID，D 读取冻结输入；学生/教师可通过各自 attempts/{attempt_id}/diagnosis-task 查询、补建或重试。详见 [内部数据接口与联调说明](内部数据接口与联调说明.md) 和 [诊断任务交付说明](诊断任务交付说明.md)。D 需适配新接收契约；尚无最终报告保存。

## 7. 超时结算与并发

取详情、查询结果、提交、保存、重复开始、读取历史及教师成绩时，对访问到的到期记录按最后保存的答案自动结算。截止瞬间不再接受新的答案；保存到期记录时先提交结算，再返回 409。超时的 submitted_at 记录截止时间，而非后台实际处理时间。

无请求时不会自行触发进程内计时器；若需要及时更新数据库状态，可让调度器周期运行：

```sh
python -m app.expire_attempts --limit 100
```

每次处理最多 1～1000 条，默认 100；输出实际处理条数。使用 MySQL 8+ 的 `FOR UPDATE SKIP LOCKED`，允许多个调度进程分批领取。大量积压可多次运行。没有配置调度器也不会允许过期后继续作答。

教师修改、发布及开始作答使用课程/试卷行锁；答案保存与评分使用作答行锁；唯一约束防止同一学生重复开始。与原有接口一样，数据库故障返回错误，不会返回未提交的成功结果。

## 8. 错误与前端处理

| HTTP | 典型原因 | 处理建议 |
| --- | --- | --- |
| 401 | 缺少、无效或过期 Token | 重新登录 |
| 403 | 学生访问教师接口，或教师访问学生接口 | 检查角色及页面入口 |
| 404 | 对象不存在、不属于自己、首次开始时未选课 | 检查 ID 与课程权限 |
| 409 | 试卷不可修改、状态不允许、基准无效、版本冲突、已结束、尚未结束、关联约束冲突 | 根据 message 刷新状态或修正流程 |
| 422 | 字段或题型规则不满足、题目/选项不属于本次作答 | 修正请求参数 |
| 503 | 数据库或事务暂不可用 | 保留本地输入，重新取状态后重试 |

## 9. 联调顺序与测试

可使用 [题库与试卷演示 SQL](../sql/seed_teacher_questions_exams.sql) 初始化 teacherAdmin 两门演示课程各 10 题的已发布测验。前置课程数据、执行顺序及重跑规则见 [SQL 说明](../sql/README.md#题库与测验初始化)。

1. 教师、学生分别登录取得 Token。教师建立课程、章节和 active 知识点并发布课程，学生选课。
2. 教师创建 active 题目，每个待诊断知识点建议至少准备 3 道题。
3. 创建草稿试卷 → PUT questions 配题和分值 → publish。
4. 学生查询课程试卷 → POST 开始 → GET 作答详情。
5. 使用快照选项 ID 和当前 revision 保存；等待成功后提交。
6. 查看结果及历史，教师查询成绩和 diagnosis-input。
7. 需要复测时创建另一份试卷，开始时关联初测作答 ID。

规则及 HTTP 回归：

