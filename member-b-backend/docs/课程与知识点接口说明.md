# 课程、章节、知识点及选课接口

本文对应 `app/api/teacher.py`、`app/api/courses.py` 和 `app/services/courses.py` 的当前实现。模型与约束见 [数据模型详细说明](数据模型详细说明.md)，账号登录及通用响应见 [接口详细说明](接口详细说明.md)。

## 1. 认证、权限及接口清单

本地地址 `http://127.0.0.1:8000`，路径没有 `/api/v1` 前缀。以下接口全部需要登录：

```http
Authorization: Bearer <登录接口返回的access_token>
```

教师必须使用 `role=teacher` 的账号，学生选退课及“我的课程”必须使用 `role=student`。教师只能维护自己创建的课程；访问其他教师的管理详情或修改入口统一返回 404，不泄露对象是否存在。

| 方法 | 路径 | 功能 | 权限 | 成功状态 |
| --- | --- | --- | --- | --- |
| POST | `/teacher/courses` | 创建草稿课程 | 教师 | 201 |
| GET | `/teacher/courses` | 分页查询自己创建的课程 | 教师 | 200 |
| GET | `/teacher/courses/{course_id}` | 查询自己的课程详情、人数和内容树 | 所属教师 | 200 |
| PATCH | `/teacher/courses/{course_id}` | 修改名称、介绍、状态 | 所属教师 | 200 |
| POST | `/teacher/courses/{course_id}/chapters` | 添加课程章节 | 所属教师 | 201 |
| POST | `/teacher/courses/{course_id}/chapters/{chapter_id}/knowledge-points` | 添加章节知识点 | 所属教师 | 201 |
| GET | `/courses` | 分页查询已发布课程目录 | 已登录用户 | 200 |
| GET | `/courses/mine` | 分页查询自己在课的课程 | 学生 | 200 |
| GET | `/courses/{course_id}` | 查看可见课程详情 | 已登录用户，按可见性规则处理 | 200 |
| PUT | `/courses/{course_id}/enrollment` | 当前学生加入课程或重新加入 | 学生 | 200 |
| DELETE | `/courses/{course_id}/enrollment` | 当前学生退课，保留关系记录 | 学生 | 200 |

创建课程时不能提交 `teacher_id`，选课时不需要提交 `student_id`；两者都由当前登录凭证确定。没有新增独立发布路径，发布和归档均通过 PATCH 的 `status` 字段完成。

本次不提供章节和知识点的修改、删除、重排接口，不提供课程物理删除及先修关系 HTTP 接口。

## 2. 通用输入、响应和错误

有请求体时使用 `Content-Type: application/json`。请求体禁止额外字段；字段类型、长度或枚举不合法时返回 422。

成功响应包装：

```json
{
  "code": 0,
  "message": "ok",
  "data": {},
  "request_id": "example-request-id"
}
```

HTTP 201 的业务 `code` 同样为 0。响应头有 `X-Request-ID`，时间字段为 Unix 秒级整数。下文 JSON 主要展示 `data` 或请求体，不省略接口实际的公共响应包装。

| HTTP 状态 | 典型消息 | 含义 |
| --- | --- | --- |
| 401 | `请先登录`、`登录状态已失效` | 无有效登录凭证 |
| 403 | `需要教师权限`、`需要学生权限` | 当前角色不允许调用该接口 |
| 404 | `课程不存在或无权访问` | 课程不存在、非当前教师所有或对当前用户不可见 |
| 404 | `章节不存在或不属于指定课程` | 添加知识点时章节不属于路径课程或不存在 |
| 404 | `选课记录不存在` | 尚未选课时调用退课 |
| 409 | `名称或关联记录已存在` | 唯一约束冲突，例如章节或章节内知识点重名 |
| 409 | `关联数据不存在或仍被引用` | 数据库外键冲突 |
| 409 | 具体状态冲突消息 | 不允许发布、选课或新增内容，详见各接口 |
| 422 | `请求参数不符合接口约定` | 字段、分页参数不合法或提交只读字段 |
| 503 | `课程服务暂不可用，请稍后重试` | 课程数据库查询、写入或提交失败 |

鉴权数据库故障也可能返回 `503 登录凭证验证服务暂不可用，请稍后重试`。业务异常会释放数据库事务；写入失败不会返回成功或向响应暴露底层 SQL、连接信息。

## 3. 课程状态与统计规则

| 当前状态 | 允许设置的状态 | 学生可新增选课 | 教师可新增章节、知识点 |
| --- | --- | --- | --- |
| `draft` | `draft`、`published`、`archived` | 否 | 是 |
| `published` | `published`、`archived` | 是 | 是 |
| `archived` | `archived` | 否 | 否 |

首次发布必须存在该课程的至少一个 `active` 知识点。知识点的复合外键保证该点属于真实章节，因此同时满足至少一个章节的条件。只有章节、只有停用知识点，均不能发布，返回 409。

发布后不能改回草稿；归档后本次版本不提供重新发布功能。所有状态都允许所属教师修改名称、介绍。归档保留课程及全部选课记录，已有在课学生仍可查看该课程内容；不会自动将选课记录改成 `withdrawn`。

`enrollment_count` 是只读计算字段：统计该课程 `course_enrollments.status='active'` 的记录数，已退课记录不计入。它不是 `courses` 的数据库列，客户端不能修改。

创建、状态修改、添加内容、选退课写操作先锁定课程行，在同一事务内完成校验和提交，避免归档与选课并发时绕过状态限制。课程列表按 `created_at DESC, id ASC` 排序；内容树的章节和知识点各按 `sort_order ASC, id ASC` 排序。

## 4. 创建课程

`POST /teacher/courses`，无需提交课程 ID、教师 ID、状态或时间戳。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `name` | string | 是 | 去除首尾空白后 1～100 字符，不能全为空白 |
| `description` | string 或 null | 否 | 最长 10000 字符，默认 null |

```json
{"name": "数据结构", "description": "学习线性表、栈、队列和树。"}
```

HTTP 201 的 `data` 示例：

```json
{
  "id": "example-course-id",
  "name": "数据结构",
  "description": "学习线性表、栈、队列和树。",
  "teacher_id": 7,
  "status": "draft",
  "created_at": 1800000000,
  "updated_at": 1800000000,
  "enrollment_count": 0
}
```

后端生成 UUID 十六进制 ID，状态固定从 `draft` 开始。课程名称允许重复。该对象的八个响应字段在后文统称“课程基本对象”，其中 `enrollment_count` 为派生统计字段。

## 5. 查询教师自己的课程

`GET /teacher/courses`，查询范围固定为当前教师本人，不接受通过教师 ID 切换到他人的课程。

| 查询参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `page` | integer | 1 | 至少为 1 |
| `page_size` | integer | 20 | 1～100 |
| `keyword` | string | 不筛选 | 最长 100 字符，按课程名称包含搜索；首尾空白去除，`%`、`_` 按普通字符处理 |
| `status` | string | 全部状态 | 可选 `draft`、`published`、`archived` |

例如：`GET /teacher/courses?page=1&page_size=20&status=published`。

列表 `data` 结构：

```json
{"items": [], "total": 0, "page": 1, "page_size": 20}
```

`items` 中每项为课程基本对象，包含实际选课人数；`total` 为当前教师在筛选条件下的总数，而不是本页条数。超出末页返回空数组，不返回 404。统计人数按本页课程批量查询，不会逐课程查询人数。

## 6. 教师课程详情

`GET /teacher/courses/{course_id}`，仅所属教师可见。

`data` 包含课程基本对象，并增加 `chapters` 数组。每个章节包含：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id`、`course_id` | string | 章节及课程 ID |
| `name` | string | 章节名称 |
| `description` | string 或 null | 章节介绍 |
| `sort_order` | integer | 排序值 |
| `created_at`、`updated_at` | integer | Unix 秒级时间戳 |
| `knowledge_points` | array | 本章节知识点，教师可见 active 和 disabled 两种状态 |

每个知识点包含 `id`、`course_id`、`chapter_id`、`name`、`description`、`sort_order`、`status` 七个字段，没有额外时间戳字段。没有章节时返回 `chapters: []`；章节中没有知识点时返回 `knowledge_points: []`。

内容树示例，仅展示 `chapters`：

```json
[
  {
    "id": "example-chapter-id",
    "course_id": "example-course-id",
    "name": "栈与队列",
    "description": null,
    "sort_order": 1,
    "created_at": 1800000000,
    "updated_at": 1800000000,
    "knowledge_points": [
      {
        "id": "example-point-id",
        "course_id": "example-course-id",
        "chapter_id": "example-chapter-id",
        "name": "栈的基本操作",
        "description": "入栈与出栈。",
        "sort_order": 1,
        "status": "active"
      }
    ]
  }
]
```

## 7. 修改课程及发布、归档

`PATCH /teacher/courses/{course_id}`。

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `name` | string | 可省略，提供时按创建规则校验，不能为 null |
| `description` | string 或 null | 可省略，最长 10000 字符；显式 null 表示清空介绍 |
| `status` | string | 可省略；只能是三个课程状态之一，不能为 null，并遵守状态流转规则 |

至少提供一个字段，`{}` 返回 422。不接受 `id`、`teacher_id`、`created_at`、`updated_at`、`enrollment_count` 等字段。

修改名称、介绍：

```json
{"name": "数据结构基础", "description": null}
```

发布：

```json
{"status": "published"}
```

归档：

```json
{"status": "archived"}
```

成功返回 HTTP 200，`data` 为更新后的课程基本对象及选课人数，不附带内容树。只有值实际发生变化时才更新课程 `updated_at`。如果同一请求既改名称又发布，但发布条件不满足，整个请求被拒绝，不部分保存。

特殊错误：发布内容不满足条件返回 `409 发布课程前至少添加一个章节和有效知识点`；状态倒退等返回 `409 不允许该课程状态变更`。

## 8. 添加章节

`POST /teacher/courses/{course_id}/chapters`。

| 字段 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- |
| `name` | string | 是 | 去除首尾空白后 1～100 字符，同一课程内不能重名 |
| `description` | string 或 null | 否 | 最长 10000 字符，默认 null |
| `sort_order` | integer | 否 | 默认 0，范围 0～2147483647；不接受小数、布尔值或数字字符串 |

```json
{"name": "栈与队列", "description": "学习两种线性结构。", "sort_order": 1}
```

HTTP 201 的 `data` 为新章节对象，字段与第 6 节章节对象一致，但不包含 `knowledge_points` 数组。所属课程来自路径，不能通过请求体指定其他课程。归档课程新增内容返回 `409 已归档课程不能新增章节或知识点`。

## 9. 添加章节知识点

`POST /teacher/courses/{course_id}/chapters/{chapter_id}/knowledge-points`。

| 字段 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- |
| `name` | string | 是 | 去除首尾空白后 1～100 字符，同一章节内不能重名 |
| `description` | string 或 null | 否 | 最长 10000 字符，默认 null |
| `sort_order` | integer | 否 | 默认 0，整数范围与章节相同 |
| `status` | string | 否 | `active` 或 `disabled`，默认 active |

```json
{"name": "栈的基本操作", "description": "入栈与出栈。", "sort_order": 1, "status": "active"}
```

必须是当前教师的课程，且章节属于路径指定的课程；不接受请求体中的 `course_id`、`chapter_id` 或自定义 ID。应用校验与数据库复合外键共同约束课程、章节一致性。归档课程禁止新增知识点。

HTTP 201 的 `data` 为第 6 节描述的七字段知识点对象。新增 disabled 知识点不会满足课程发布所需的有效知识点条件。

## 10. 可选课程目录

`GET /courses`，学生和教师登录后均可查询，固定只返回 `published` 课程。

支持 `page`、`page_size`、`keyword`，规则与第 5 节相同；没有可切换的状态筛选参数。返回公共分页对象。每项为课程基本对象；学生查询时额外返回：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `is_enrolled` | boolean | 当前学生是否存在 active 选课记录 |
| `enrolled_at` | integer 或 null | 当前在课记录的最近加入时间，未在课为 null |

教师查询目录时不附带这两个学生字段。已归档课程不会出现在目录，即使某个学生此前已选。

## 11. 学生的已选课程

`GET /courses/mine`，仅学生可用。支持 `page`、`page_size`、`keyword`、`status`，取值与第 5 节相同。

仅查询当前学生 `status='active'` 的选课记录，退课记录不出现在列表。课程可为 published 或 archived；归档不会使学生自动退课，因此仍出现在“我的课程”中并保留课程状态。正常业务流程不会产生已选草稿课程；按 draft 筛选通常为空。

响应为公共分页对象，列表项为课程基本对象，加上 `is_enrolled: true` 和 `enrolled_at`。查询结果不包含其他学生的选课。固定路径 `/courses/mine` 在动态详情路径前注册。

## 12. 学生或登录用户的课程详情

`GET /courses/{course_id}`。

| 情况 | 可见内容 |
| --- | --- |
| 所属教师访问自己的课程 | 任意状态可见，包含所有章节及 active、disabled 知识点 |
| 学生存在 active 选课记录，课程为 published 或 archived | 基本信息、人数和内容树，知识点仅包含 active |
| 其他登录用户访问 published 课程 | 基本信息和人数，`chapters: null`，不能预览完整内容树 |
| 非所属教师访问 draft，或未在课用户访问 archived | 404 |

响应为课程基本对象加 `is_enrolled`、`enrolled_at` 和 `chapters`。教师的 `is_enrolled` 为 false；该字段表示学生选课，不表示教师的课程所有权。空内容树 `[]` 与无内容访问权限 `null` 含义不同。

## 13. 选课与退课

### 13.1 加入课程

`PUT /courses/{course_id}/enrollment`，只使用当前学生身份，无需请求体。

课程必须为 published，即使已经选过，课程当前归档后再次调用加入接口也返回 `409 只能选择已发布的课程`。

- 首次加入：新增联合主键记录，状态 active，设置两个时间戳。
- 已在课重复加入：返回已有记录，不新增，不重置加入或更新时间。
- 已退课重新加入：复用原记录，将状态恢复 active，重设加入及更新时间。

HTTP 200 的 `data` 示例：

```json
{
  "course_id": "example-course-id",
  "student_id": 8,
  "status": "active",
  "enrolled_at": 1800000000,
  "updated_at": 1800000000
}
```

课程锁和联合主键一起防止重复选课。加入成功后，课程的 active 选课人数会在后续统计中体现；课程表不维护额外人数列。

### 13.2 退出课程

`DELETE /courses/{course_id}/enrollment`，只使用当前学生身份，无需请求体。DELETE 表示取消选课，并不物理删除数据库行。

- 没有该课程或没有本人选课记录，返回 404。
- 在课时改为 withdrawn，保留原 enrolled_at，更新 updated_at。
- 已退课重复调用仍返回 200，不再更新时间。
- 已归档课程允许退课，但不能重新加入。

成功 `data` 与加入接口相同，`status` 改为 `withdrawn`。退课后不再计入人数或“我的课程”，失去基于当前选课关系的完整内容树访问权；关系记录仍保留，供后续历史功能使用。

## 14. 一次完整联调

1. 教师注册或登录，取得教师 Token。
2. POST `/teacher/courses` 创建草稿，记录返回的课程 ID。
3. POST `/teacher/courses/{course_id}/chapters` 创建章节，记录章节 ID。
4. POST `/teacher/courses/{course_id}/chapters/{chapter_id}/knowledge-points` 添加 active 知识点。
5. GET 教师课程详情确认内容，再 PATCH 课程 `status=published`。
6. 学生登录，GET `/courses` 找到课程，PUT enrollment 加入。
7. GET `/courses/mine`、GET 课程详情，确认在课及内容可见。
8. 教师 GET 自己的课程详情，确认 `enrollment_count`。
9. 学生 DELETE enrollment 退课，再 PUT 重新加入，确认没有新增重复关系。
10. 教师 PATCH 归档课程，确认目录不再展示、新选课被拒绝，但在课学生仍能从自己的课程访问。

调用命令示例（将占位符替换为实际值）：

```sh
curl -X POST http://127.0.0.1:8000/teacher/courses \
  -H 'Authorization: Bearer <teacher_token>' \
  -H 'Content-Type: application/json' \
  -d '{"name":"数据结构","description":"学习基本数据结构。"}'

curl -X PATCH http://127.0.0.1:8000/teacher/courses/<course_id> \
  -H 'Authorization: Bearer <teacher_token>' \
  -H 'Content-Type: application/json' \
  -d '{"status":"published"}'

curl -X PUT http://127.0.0.1:8000/courses/<course_id>/enrollment \
  -H 'Authorization: Bearer <student_token>'

curl http://127.0.0.1:8000/courses/mine \
  -H 'Authorization: Bearer <student_token>'
```

本次接口复用既有课程相关模型，无新增表结构。已有模型表、唯一约束和复合外键必须正确创建；`create_all` 不会更新旧表定义。自动化回归使用数据库替身，验证路由、规则、SQL 过滤和事务调用，不等于真实 MySQL 并发测试。
