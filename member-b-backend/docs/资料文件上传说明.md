# 资料 PDF、Word 上传与原文件下载

本功能属于 B 的资料业务。教师上传 PDF 或 DOCX 后，B 提取正文、保存知识点关联，并将原文件保存到私有目录。学生继续使用原有资料接口阅读提取后的文字，也可在鉴权后下载原件。本功能不调用 C/D，不表示资料已建立 RAG 索引。

## 1. 安装和启动

本次新增 python-multipart、pypdf 依赖，使用项目的 Python 环境执行：

```sh
python -m pip install -r requirements.txt
python -m app
```

如果使用 uvicorn --reload，也应安装依赖后重启。启动时自动创建缺失的 resource_files 表，不修改既有 course_resources 列。也可单独执行 [create_resource_file_table.sql](../sql/create_resource_file_table.sql)，先修改 USE 中的目标库名。全新资料模块建表文件 [create_course_resource_tables.sql](../sql/create_course_resource_tables.sql) 已包含三张资料表。

原文件默认存储目录为项目内 `data/resource_files`，已加入 .gitignore。可通过 .env 的 RESOURCE_UPLOAD_DIR 设置；相对路径以项目根目录为基准。目录在首次成功解析并保存文件时创建，应用账号需要读写权限。

## 2. 支持范围

| 项目 | 限制 |
| --- | --- |
| PDF | 有文本层的 PDF，最大 300 页；不支持密码保护 |
| Word | .docx，提取正文段落和表格；不支持 .doc/.docm 或包含 VBA 宏的文件 |
| 文件大小 | 最多 10 MiB，即 10485760 字节 |
| 正文长度 | 最多 200000 字符，超出时拒绝，不静默截断 |
| DOCX 包结构 | 解压内容总计最多 30 MiB，正文 XML 最多 8 MiB，最多 2000 个条目 |
| 文件数量 | 每次一个文件 |

旧 .doc 请在 Word 中另存为 .docx。扫描件或纯图片文档如果无法提取文字，返回 422，需先 OCR。仅部分 PDF 页面无文字时，保留可提取内容，并在 extraction_info.empty_text_pages 中列出未提取出文字的页码（从 1 开始）；这不保证其他页的文字提取完整。

提取结果用于正文阅读，不保留完整页面版式。DOCX 不提取页眉页脚、嵌入图片、批注和复杂公式；PDF 表格、数学公式及多栏排版可能需要人工校对。可以通过原有 PATCH 接口修改提取正文。

## 3. 上传接口

```http
POST /teacher/courses/{course_id}/resources/upload
Authorization: Bearer <教师 access_token>
Content-Type: multipart/form-data
```

所属教师才能上传；归档课程拒绝新增。先校验课程及知识点权限，再解析文件；解析期间不持有课程写锁。保存前会再次校验，防止处理期间课程被归档。

表单字段：

| 字段 | 必填 | 类型/填写方式 |
| --- | --- | --- |
| file | 是 | 选择一个 PDF 或 DOCX 文件 |
| title | 是 | 普通文本，去首尾空白，1～200 字符 |
| knowledge_point_ids | 是 | ID 数组；Swagger 每项填写一个 ID，表单可重复此字段；兼容 JSON 数组字符串和英文逗号分隔 |
| source | 否 | 普通文本，默认“课程教师自编材料”；显式传入时不能为空，最多 1000 字符 |

knowledge_point_ids 支持 1～50 个不重复的本课程 active 知识点，接收以下四种等价形式：单个 ID、重复同名表单字段、英文逗号分隔的 ID、JSON 数组字符串。服务端统一转换为 ID 列表后，再校验长度、去重和课程归属。JSON 数组有语法错误时仍返回 422，不会当作普通 ID 保存。

字段首尾空白会去除；空 ID、末尾多余逗号、JSON null/对象/非字符串元素、重复 ID 和超过 50 个 ID 都会被拒绝。只有 knowledge_point_ids 可以重复，file、title、source 仍只能出现一次；额外字段返回 422。

### 3.1 Swagger 测试步骤

1. 访问 `/docs`，教师登录并 Authorize。
2. 打开上传接口，点击 Try it out。
3. course_id 填真实课程 ID。已导入演示数据时，可用 `demo-course-ds-teacher-2`。
4. file 选择本地文件，title 填标题，knowledge_point_ids 每项填单个 ID，例如 `demo-kp-stack-concept`；多个 ID 可添加多项，也可填 `demo-kp-stack-concept,demo-kp-stack-operations`。
5. Execute，成功应返回 HTTP 201。保存 data.id 作为资料 ID。

### 3.2 curl 示例

```sh
curl -X POST 'http://127.0.0.1:8000/teacher/courses/demo-course-ds-teacher-2/resources/upload' \
  -H 'Authorization: Bearer <access_token>' \
  -F 'title=栈的学习资料' \
  -F 'source=课程教师自编材料' \
  -F 'knowledge_point_ids=demo-kp-stack-concept' \
  -F 'knowledge_point_ids=demo-kp-stack-operations' \
  -F 'file=@/实际文件路径/栈的学习资料.pdf'
```

curl 使用 -F 时自动生成 multipart 边界，不手动添加 application/json 请求头。Word 文件将 file 路径改成实际 .docx 路径。

已有前端使用 `formData.append("knowledge_point_ids", JSON.stringify(ids))` 仍可使用。新前端建议逐项 append：

```javascript
for (const id of ids) {
  formData.append("knowledge_point_ids", id);
}
```

旧版本强制按 JSON 字符串解析，单个 ID 会报“knowledge_point_ids 必须是 JSON 数组字符串”。更新后需重启后端并刷新 /docs，让 Swagger 加载新的数组字段定义；无需修改数据库。

## 4. 成功结果与后续操作

上传成功响应沿用 B 的 `{code:0,message:"ok",data:...,request_id:...}` 包装。data 与创建纯文本资料相同：id、course_id、title、text、source、version、status、knowledge_point_ids、created_at、updated_at，额外包含 original_file 元数据和 index_status（上传初始为 pending）。保存成功不代表 C 已建立索引；后续由 C 拉取 B 已提取的正文并回报，见 [内部数据接口与联调说明](内部数据接口与联调说明.md)。

| original_file 字段 | 含义 |
| --- | --- |
| id | 原文件元数据 ID；下载接口使用资料 ID，不使用此 ID |
| resource_version | 原件对应的资料版本，初次上传为 1 |
| original_filename | 清理客户端路径后的原文件名 |
| media_type | 根据实际支持格式确定的 PDF/DOCX 类型，不信任客户端 MIME |
| size_bytes | 原始文件字节数 |
| sha256 | 原文件 SHA-256 摘要 |
| extraction_info | 本次提取信息 |
| created_at | 上传保存时间，Unix 秒 |

PDF extraction_info 示例：

```json
{
  "format": "pdf",
  "page_count": 3,
  "empty_text_pages": [2],
  "text_characters": 1200
}
```

DOCX extraction_info 示例：

```json
{
  "format": "docx",
  "text_characters": 1200
}
```

教师与学生的资料列表、详情，以及修改后的详情均包含 original_file。纯文本创建的资料该字段为 null。响应不会返回 storage_key、本机目录或静态公开 URL。

更新 title、text、source 或知识点仍使用 PATCH `/teacher/resources/{resource_id}`，携带 expected_version。**修改正文不改写原 PDF/DOCX**：例如正文已是 version=2，original_file.resource_version 仍为 1，表示下载的是初次上传的原件。本轮没有替换原文件接口，也不把后续正文修改重新导出成 Word/PDF。

## 5. 原文件下载

| 方法 | 路径 | 权限 |
| --- | --- | --- |
| GET | `/teacher/resources/{resource_id}/file` | 所属教师，可查看归档课程及逻辑删除记录的原件 |
| GET | `/resources/{resource_id}/file` | 有效选课学生，课程 published/archived，资料 active |

成功直接返回文件二进制、正确 Content-Type 和 attachment 下载文件名，不包 JSON。响应包含 Cache-Control: private, no-store 以及 X-Content-Type-Options: nosniff。

没有原件的纯文本资料返回 404。未选课、已退课、其他教师、其他学生不能绕过权限；删除资料后，学生不能再下载，所属教师仍可核对原件。资料逻辑删除不会立即删除磁盘原件，目录不挂载为公开静态文件服务。

原文件在磁盘缺失、大小不符或存储记录异常时返回 503，正文数据仍保留。部署和备份时应同时保存数据库及 RESOURCE_UPLOAD_DIR；只复制数据库不会复制原文件。

## 6. ResourceFile / resource_files 模型

文件上传功能新增一张表，既有两张资料表不加列；后续内部对接另新增 resource_index_states。当前全项目共十九个启用模型，索引状态见 [内部数据接口与联调说明](内部数据接口与联调说明.md)。

| 字段 | MySQL 类型 | 约束与说明 |
| --- | --- | --- |
| id | VARCHAR(64) | 主键，UUID |
| resource_id | VARCHAR(64) | NOT NULL、UNIQUE，外键 course_resources.id，RESTRICT；一份资料最多一个上传原件 |
| resource_version | INTEGER | NOT NULL，CHECK ≥1，记录原件对应版本 |
| original_filename | VARCHAR(255) | NOT NULL，文件名不包含客户端目录 |
| media_type | VARCHAR(100) | NOT NULL |
| size_bytes | BIGINT | NOT NULL，CHECK >0 且 ≤10485760 |
| sha256 | VARCHAR(64) | NOT NULL，允许不同资料上传相同内容 |
| storage_key | VARCHAR(100) | NOT NULL、UNIQUE，随机 UUID 加扩展名，仅服务端使用 |
| extraction_info | JSON | NOT NULL，提取格式、字数、PDF 页码等 |
| created_at | BIGINT | NOT NULL，ORM 默认当前 Unix 秒 |

原件和正文、标签、元数据的创建由同一上传业务协调。解析或明确的提交前数据库失败不会返回成功，并清理本次写入的原件；文件保存失败不创建资料。MySQL 与文件系统不是一个事务，commit 连接中断时结果可能未知，此时保留原件供管理员根据 resource_files.storage_key 核对，避免误删可能已经提交的引用。此类失败仍返回 503。

## 7. 错误与验证

| HTTP | 典型原因 |
| --- | --- |
| 401/403/404 | 未登录、角色错误、无课程/资料权限；与原资料规则一致 |
| 409 | 课程归档、知识点不可用或跨课程、数据库关联冲突 |
| 413 | 文件、页数、正文、DOCX 解压内容或 PDF 内部结构超过限制 |
| 415 | 不支持的扩展名、旧 DOC 或包含宏的 Word |
| 422 | 表单错误、空文件、伪造扩展名、损坏/加密文件或没有可提取文字 |
| 503 | PDF 依赖未安装、磁盘写入/读取失败、数据库故障 |

```sh
python -m pytest -q tests/test_resource_files.py tests/test_resources.py tests/test_startup.py tests/test_mysql_resources.py
```

默认测试以真实 PDF/DOCX 字节验证解析和私有文件保存，数据库使用替身。TEST_MYSQL_URL 显式配置后，独立随机测试库还验证实际上传、元数据提交、原件下载和权限；未配置时跳过真实 MySQL 测试。

实现参考：[FastAPI 表单与文件](https://fastapi.tiangolo.com/tutorial/request-forms-and-files/)、[pypdf](https://pypi.org/project/pypdf/6.21.4/)。DOCX 使用 Python 标准库读取 ZIP/XML，不执行宏、不提取压缩包到磁盘、不访问文档中的外部链接。
