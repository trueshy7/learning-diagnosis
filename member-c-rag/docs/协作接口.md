# C 与 B D 的协作接口

对接依据为组长 `ts` 提交 `37c05764e5041b2c47c567a4db5b950161bf6c94` 的 `member-b-backend/docs/内部数据接口与联调说明.md`。它优先于旧的 `/internal/v1` 设计稿。B 没有 `/api/v1` 前缀，C 不访问 B 数据库。

## C 主动同步 B

使用 `B_URL` 和 `B_C_KEY`；后者对应 B 的 `C_SERVICE_KEY`，不是教师或学生登录令牌。成功先解包 `{code,message,data,request_id}` 的 data。

| 方法 | B 路径 | C 行为 |
|---|---|---|
| GET | /internal/courses | limit/after_id 分页遍历授权课程 |
| GET | /internal/courses/{course_id}/resources | 完整扫描 active 与 deleted，不把时间或上次 ID当永久水位 |
| GET | /internal/resources/{resource_id} | 获取当前正文、标签、version、content_hash 和 index_state |
| PUT | /internal/resources/{resource_id}/index-state | 持久化后回报 ready，清理后回报 deleted；错误只回报约定枚举 |

C 每轮重新从第一页扫描。相同版本会核验并复用本地索引，不重复添加片段；B 标记 ready 但 C 本地缺失时仍重建。回报 409 最多重新读取三次，再留待下轮；某资源失败不阻断其他资源，课程出口不可用则本轮失败，周期任务记录错误类型并重试。

B 摘要的字段为 course_id、title、text、source、按 Unicode 排序的 knowledge_point_ids；JSON 键排序、ensure_ascii=False、分隔符为逗号和冒号、不缩进、不额外归一正文，UTF-8 SHA256。`catalog.b_content_hash` 与组长算法一致。

本地调用示例：

```python
from rag_service.catalog import KnowledgeIndex
from rag_service.config import Settings
from rag_service.sync import BackendSync

index = KnowledgeIndex(Settings.from_env())
worker = BackendSync(index, base_url, c_service_key)
try:
    result = worker.run_once()
finally:
    worker.close()
```

`KnowledgeIndex.ingest_record(ResourceRecord(...))`、`delete_version(resource_id, course_id, version)`、`resource_state(resource_id)`、`status()`、`rebuild()` 是 Python 服务入口。`files.ingest_file(index, resource_meta, file_path)` 支持本地原件。禁止在另一个写进程同时操作相同目录。

## D 受限检索

C 地址默认 `http://127.0.0.1:8001`。正式 B 资料用 POST `/internal/retrieve-scoped`，也提供相同合同的 `/internal/v1/retrieve` 别名；这是 C 新入口，不表示 B 采用了旧 V1 路由。

```json
{
  "course_id": "demo-course-ds-teacher-2",
  "query": "栈的后进先出及入栈出栈",
  "knowledge_point_ids": ["demo-kp-stack-concept"],
  "resource_scope": [
    {
      "resource_id": "替换为B目录中的真实ID",
      "resource_version": 1,
      "document_id": "替换为B目录中的真实文档ID",
      "content_hash": "替换为B目录中的64位摘要"
    }
  ],
  "top_k": 5
}
```

resource_scope 从 B 冻结的 resource_catalog 获取，只投影 resource_id/resource_version/document_id/content_hash，不传 title 等多余字段。content_hash 可省略，但已有时建议传入。空数组返回空证据。知识点采用交集匹配，空知识点数组不额外限制标签，课程与资源范围仍生效。

响应直接为 JSON，含 mode、index_version、course_id、evidence、unavailable_resources、insufficient_evidence、reason、fallback_reason、retrieval_id、candidate_count、elapsed_ms。每个 evidence 含 evidence_id、resource_id、resource_version、course_id、document_id、chunk_id、knowledge_point_ids、text、score、location、source、title、index_version。

location 为 `{kind:"text",start:0,end:100,chapter:"章节"}`；直接 PDF 导入可附 pages。text 是精确原文，score 是相关度，不是概率。资料版本不可用返回 unavailable_resources 的 not_available 或 version_changed，不悄悄改用新版本。可选 index_version 不符返回 409；输入不符 422；索引无法读取 503。

模式为 keyword_demo、vector_rag、keyword_fallback 或仅用于测试的 vector_hash_test。向量失败与没命中不同；D 应在 fallback/insufficient_evidence 时如实显示，不编造证据。

旧 POST `/internal/retrieve` 的请求和响应主字段保留，供 `course-ds` 原演示使用。B 同步课程必须迁移到受限入口。`ts` 当前 D 的 HttpRetriever 仍使用旧入口，适配新业务数据的责任在 D；本交付提供了可调用接口，没有擅自修改 D 的诊断业务。

## 引用校验与来源显示

POST `/internal/citations/validate`：

```json
{"retrieval_id":"本次检索返回的ID","evidence_ids":["本次实际返回的证据ID"]}
```

返回 valid、invalid_ids、reason。未知查询、超时、重启、编造证据或资源更新删除后均不能作为有效当前引用。B 应保存历史报告的证据快照与映射；内存校验缓存不是历史报告数据库。

其他接口：GET `/internal/index-status`、GET `/internal/resources/{resource_id}/state`、GET `/internal/resources?course_id=...`、POST `/internal/rebuild`。旧文本入库和 DELETE 不能覆盖/删除 B 管理的资料，B 资料删除以其墓碑为准。

C 可选 `RAG_SERVICE_KEY` 启用 Bearer 凭证，`RAG_ALLOWED_COURSE_IDS` 限定允许课程。旧 D 尚未发送 C 接收密钥，启用后 D 需同步加头；本机兼容测试默认回环地址、不设 C 接收密钥。A 仍只访问 B，不拿内部密钥。

A 的引用卡片可展示 title、source、text、章节/字符范围、直接解析时的页码。需要原件时走 B 的鉴权下载，不把 source 字符串或 C 磁盘路径当作可公开下载链接。
