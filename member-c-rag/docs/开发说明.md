# 成员 C 模块设计与复现

本模块把课程资料转换为可追溯的证据，为 D 提供检索工具。B 是课程、知识点、资源元数据和版本的唯一业务来源；C 只保存正文副本、片段、最高版本和删除墓碑及派生向量。启动步骤见本模块 README。

## 数据处理

`parsing.parse_file` 支持 UTF-8 或 GB18030 文本、Markdown、文本型 PDF；限制 20 MiB、PDF 500 页和正文 200000 字符。PDF 多数页面重复的边缘行可作为页眉页脚移除，保留原始页码映射。空文件、空白文本、异常编码、加密 PDF、无可提取文字和格式错误有独立错误码；不运行 OCR。

`files.ingest_file` 把有效原件按 SHA256 保存到 `data/imports`，追加不含正文的解析日志；失败文件不建立可检索记录。B 已提取好的 text 不再经过清洗，避免改变 B 的规范摘要及字符偏移。

`segments.split_document` 优先在标题、段落、页边界附近切分，超过长度再按字符窗口切分，保持重叠。记录正文原始 Unicode 字符区间、章节、可用时的 PDF 页码、内容摘要。位置采用从零开始、左闭右开；返回 text 必须精确等于对应原文范围。

默认 400 字符、60 字重叠，评测另比较 700/100。中文模型最大输入 512 token，中文字符和 token 不完全等价；对于真实长教材应检查分词后长度，必要时收紧切分。当前资料最长约 407 字符，配置差异对本语料影响较小。

## 索引与版本

`catalog.KnowledgeIndex` 的活动目录格式为 `catalog-2`。资源更新先校验 B 的规范 JSON 摘要，校验最高版本和课程归属，再切片。相同版本完整请求相同则幂等；同版本不同内容拒绝，低版本拒绝。一个 resource_id 对应一个当前文档，不把历史版本与当前版本同时返回。

删除保留最高版本墓碑，重复删除幂等，迟到入库和删除不能覆盖较高版本。已删除资源不恢复，重新上传需新业务 ID。B 已 ready 的相同版本文档 ID在本地丢库重建时优先复用；否则按资源 ID 与版本生成稳定 ID。

向量模式构建新的不可变 Chroma 集合，完成后再原子切换 JSON 活动目录；失败时保留之前版本。活动目录包含内容、模型签名和不透明 index_version。旧集合清理失败只会遗留不可达数据；下次成功提交可清理。向量库丢失时可由正文目录重建，目录丢失时从 B 完整拉取。

采用单进程锁；不能同时运行服务、导入工具和独立同步工具写同一路径。完整重建按小型课程设计规模实现，每次变更会重建该代集合；更大语料需再实现增量代际构建和更严格任务调度。

## 嵌入与检索

`embeddings.Embeddings` 支持 FastEmbed 中文本地模型和兼容 embeddings JSON 的 HTTP 服务。模型、版本、维度、批次、缓存、超时由环境变量配置；拒绝非有限数字、零向量、维度和数量不一致。模型签名变化不能混入旧空间；查询可明确降级，正式重新建库后才恢复向量模式。

`chroma_store.ChromaStore` 显式传向量并关闭默认 embedding_function。使用余弦距离，以 `1-distance` 为相关度，不是可信概率。检索先限定课程、资源版本、文档、摘要和知识点交集，再以允许片段 ID 进行 ANN 排序；不能先全库 Top-K 再过滤而导致授权结果漏检。

向量最低相关度默认 0.45；关键词最低词项覆盖率默认 0.20。阈值只是本地工程参数，不是通用判定无答案的理论保证。总证据最多 6000 字符，单次 Top-K 为 1—10，查询最多 1000 字符；不会截断证据而保留错误的定位。

空结果带不足标记和原因；索引损坏返回 503。向量故障允许时返回 `keyword_fallback`，不会改名成向量成功。资料中的指令、代码和 URL 都是数据，解析器不执行它们；D 把证据交给模型时仍需作为不可信材料隔离。

## 引用与调用

每次受限查询生成 retrieval_id，并在内存中最多保存 256 个、30 分钟有效的返回证据集合。引用校验仅接受这次查询已返回的 evidence_id，并再次检查当前资源版本和删除状态。服务重启后旧 retrieval_id 失效，历史报告须由 B 保存证据文本和映射。

`location` 是结构化位置，B 当前同步只有纯文本，不能推测 PDF 页码；C 直接解析 PDF 时才有原始页码。A 展示来源文本，安全下载走 B 原件接口，不能直接使用 C 磁盘路径。C 接收端可配置单个服务密钥和课程白名单；它不是学生权限系统，正式部署还需与 B/D 确认调用方身份分权。

## 测试边界

`scripts.check` 同时运行原有兼容测试、版本与引用测试、解析测试、真实 Chroma 持久化测试和 B 同步合同测试。Chroma 持久化测试使用明确标为 hash_test 的向量，不证明语义质量；语义质量由真实中文模型评测单独证明。

B 同步使用 httpx.MockTransport 核对组长现有路由、外层包装、摘要和回执；这不等于真实 MySQL 联调。`scripts.check_d_integration` 启动真实 C HTTP 进程并调用仓库 D 的实际检索代码，保存真实响应；D 仍使用规则解释，不能据此声称已完成 LLM 正常闭环。

## 主要文件

| 文件 | 责任 |
|---|---|
| rag_service/contracts.py | B 资源记录和 D 受限检索类型 |
| rag_service/sync.py | 拉取课程/资料、版本处理、回报索引状态 |
| rag_service/parsing.py 与 files.py | 文件解析、备份、失败日志 |
| rag_service/segments.py | 分段和原文定位 |
| rag_service/catalog.py | 版本目录、墓碑、检索和引用校验 |
| rag_service/embeddings.py 与 chroma_store.py | 嵌入、派生向量和代际切换 |
| rag_service/main.py | 内部 HTTP、可选鉴权、同进程同步 |
| scripts/build_knowledge_index.py | 清单入库与导出 |
| scripts/evaluate.py | 固定20题和无答案对照 |
| rag_service/index.py | 保留的初始关键词基线，不是新版服务入口 |
