# 成员 C 开发说明

项目：基于 RAG 与多智能体协作的个性化学习诊断与推荐系统。

本说明与本目录代码配套。初始项目打通“导入文本 → 标准化 → 分段 → 保存 → 关键词检索 → 来源引用”流程，给后续语义 RAG 开发提供可运行起点。

## 1. 职责与协作边界

成员 C 维护课程资料及检索证据；成员 B 负责账号、课程、学习记录、对外鉴权和业务数据；成员 D 根据学情诊断调用检索，再组织推荐；成员 A 展示资料、引用及推荐结果。

- B 接受资料后先校验用户课程权限，再调用 C 的导入接口。初始接口只接收已提取好的纯文本。
- D 通过 HTTP 调用 C 的 `/internal/retrieve`，不直接读取 `data/index.json`。
- A 通过 B 的业务接口访问检索资料，不把初始内部服务直接暴露给用户浏览器。
- 四人联调使用课程 `course-ds`；栈知识点为 `kp-stack`，队列为 `kp-queue`。新增 ID 先由 B 统一登记。
- C 返回普通 JSON，不使用 B 的业务响应包装；D 应直接读取顶层 `evidence`。

## 3. 环境与配置

Python 3.11+；依赖安装与启动见 README。默认启动仅使用 FastAPI、Uvicorn、Pydantic。不要同时启动多个进程写同一个 JSON 文件；本版本使用进程内锁和原子替换，不提供跨进程事务。

| 配置项 | 默认值 | 作用 |
|---|---|---|
| `RAG_HOST` | `127.0.0.1` | 使用 `python -m rag_service` 时的监听地址，只允许回环地址 |
| `RAG_PORT` | `8001` | 监听端口 |
| `RAG_DATA_PATH` | `data/index.json` | 索引文件路径，相对路径以启动目录为准 |
| `RAG_SEED_ON_START` | `true` | 仅在索引文件不存在时导入两个样例 |
| `RAG_CHUNK_SIZE` | `360` | 每段最多 Unicode 字符数，允许 80–2000 |
| `RAG_CHUNK_OVERLAP` | `60` | 相邻片段重叠字符数，必须小于分段长度 |

`.env.example` 是配置样例，应用不自动读取 `.env`。可直接在终端设置环境变量；macOS / Linux 也可复制并加载：

```bash
cp .env.example .env
set -a
source .env
set +a
python -m rag_service
```

PowerShell 可使用 `$env:RAG_PORT="8001"` 等方式逐项设置。修改分段大小后，已经保存的资料不会自动重分段；执行重建入口后生效。只修改监听端口无需重建索引。

## 4. 资料与片段约定

初始版本一项资源对应一份文本。`resource_id` 和 `document_id` 由调用方显式提供，要求全局唯一。`document_id` 已属于其他资源时返回 409，避免误覆盖。资源已属于其他课程时，也返回 409。

同一 `resource_id` 再次导入视为整体替换：删除旧片段，再保存新原文及新片段，不累计重复内容。即使换了 `document_id`，同资源也只保留最新一份文本。删除操作按资源移除其全部文档与片段；重复删除成功返回计数 0。

原文先统一换行、压缩连续空行并去除首尾空白。片段位置是该**标准化后文本**中的 Unicode 字符偏移，从 0 开始，左闭右开，例如 `chars:0-360`，不是 PDF 页码或字节偏移。

片段 ID 根据 `document_id`、位置和片段文本计算。相同输入与分段配置重复导入时引用稳定；文本或分段配置改变时片段 ID 可能变化。`evidence_id` 从片段 ID 派生。`index_version: demo-1` 是索引结构版本，不代表资料修改次数。对旧推荐结果的长期引用快照，需要后续由 B / D 保存或扩展版本化能力。

## 5. 内部 HTTP 接口

所有接口仅供本机开发。当前没有 Token 校验，也没有多租户安全隔离；按课程过滤是检索逻辑，不代替权限检查。正式鉴权由 B 接入后再考虑部署。

### 5.1 健康检查

`GET /health`

```json
{"status":"ok","service":"rag","mode":"keyword_demo"}
```

### 5.2 导入资料

`POST /internal/ingest`

```json
{
  "resource_id": "res-stack-extra",
  "document_id": "doc-stack-extra",
  "course_id": "course-ds",
  "title": "栈的应用补充",
  "text": "栈适合实现撤销操作。每次新操作入栈，撤销时取出最近一次操作。",
  "knowledge_point_ids": ["kp-stack"],
  "source": "原创课程样例/栈应用补充.txt"
}
```

```json
{"document_id":"doc-stack-extra","chunks":1,"index_version":"demo-1","mode":"keyword_demo"}
```

约束：原文 1–200000 字符；标题最多 500 字符；来源最多 1000 字符；ID 最多 128 字符；最多 50 个知识点。额外未知字段被拒绝。格式或长度错误返回 422，资源 / 文档 ID 冲突返回 409。此版本不解析 PDF、Word 或网页；B 应先提取纯文本，或后续由 C 增加独立解析任务。

`source` 只是显示和追溯标签，服务不会把它作为文件路径读取，也不会访问其中的 URL。

### 5.3 检索

`POST /internal/retrieve`

```json
{
  "course_id": "course-ds",
  "query": "栈的后进先出是什么意思",
  "knowledge_point_ids": ["kp-stack"],
  "top_k": 5
}
```

返回结构如下；ID 和位置取决于原文与分段配置，此处省略具体 ID 内容：

```json
{
  "mode": "keyword_demo",
  "index_version": "demo-1",
  "evidence": [
    {
      "evidence_id": "ev-<片段摘要>",
      "document_id": "doc-stack",
      "resource_id": "res-stack",
      "chunk_id": "chunk-<片段摘要>",
      "knowledge_point_ids": ["kp-stack"],
      "text": "栈是一种后进先出（LIFO）的线性数据结构。……",
      "score": 0.5,
      "location": "chars:0-360",
      "source": "原创课程样例/栈基础.txt",
      "title": "栈：后进先出的线性结构"
    }
  ]
}
```

查询最长 1000 字符；`top_k` 限制为 1–10，默认 5。`knowledge_point_ids` 为空时仅按课程筛选；非空时按知识点交集筛选，命中任一指定知识点即可。查询没有可匹配关键词时返回空证据数组，不回退到跨课程资料。

关键词算法：中文使用相邻两个汉字组成的字组，英文和数字使用单词；在标题和片段内匹配，按已匹配词数 / 查询词数评分。相同得分按文档和片段 ID 稳定排序。该算法不理解同义词、上下文或语义相似性，存在误匹配和漏检，得分不能解释为置信度。

### 5.4 资源清单

`GET /internal/resources?course_id=course-ds`

```json
{
  "resources": [
    {"resource_id":"res-queue","title":"队列：先进先出的线性结构","knowledge_point_ids":["kp-queue"],"source":"原创课程样例/队列基础.txt"},
    {"resource_id":"res-stack","title":"栈：后进先出的线性结构","knowledge_point_ids":["kp-stack"],"source":"原创课程样例/栈基础.txt"}
  ]
}
```

### 5.5 删除与重建

`DELETE /internal/resources/res-stack` 删除该资源全部片段，并返回删除文档数和片段数。不存在时计数为 0。删除后重启不会自动恢复样例；只有索引文件完全不存在时启动才会自动初始化。

`POST /internal/rebuild` 从当前 JSON 中保存的原文重新分段，返回文档数和片段数。也可在停止服务后执行：

```bash
python -m scripts.rebuild
```

需要重新载入两个样例时，执行 `python -m scripts.seed`。该操作只覆盖两个同 ID 的样例，不清空其他资料。改动或备份 JSON 文件时应停止服务，避免并发写入。索引损坏时不要静默忽略，应先备份、查明原因，再重新导入资料；本项目没有自动恢复功能。

## 6. 来源可信与资料指令边界

检索服务只保存和返回文本，不解析或执行资料中的指令、代码、URL 或系统提示语。资料内出现“忽略以上要求”“运行命令”等语句仍是资料内容。后续 D 调用模型时，应把证据放进明确的数据区，附带来源，要求模型只将其用于作答依据；不能把资料拼接为可覆盖系统规则的指令。

无匹配证据时，D 应输出“未检索到依据”并给出需要补充的资料，不能把空结果解释成已证实的结论。展示来源时由 A 转义文字，不直接执行 HTML；调用外部链接时遵循应用的链接策略。

## 7. 测试与演示评测

```bash
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
python -m scripts.evaluate
```

测试使用临时目录，不改动真实 `data/index.json`。覆盖重复导入及引用稳定、课程和知识点过滤、资源完整删除、片段偏移与原文一致、替换后持久化、跨资源文档 ID 冲突、重建保持来源、查询长度和 Top-K 限制。

共 13 项测试：8 项索引测试，以及 5 项基于 TestClient 的 HTTP 测试。HTTP 测试覆盖健康检查、种子资源、检索响应字段、导入与覆盖、删除后重启不恢复、重建、课程过滤和非法输入。HTTPX 只在测试时需要，默认服务启动不需要安装开发依赖。

`questions.json` 只有 4 道演示问题，用来验证管线和示例命中情况。即使全部命中，也不能证明课程知识库检索质量、学习效果或生产性能。第 5 周应补充人工标注题，包含同义问法、无答案、知识点混淆、来源错误、提示注入等情形，分别记录关键词和向量方法的结果。

## 8. 扩展为真实语义 RAG

`rag_service/vector_extension.py` 提供 `EmbeddingAdapter` 协议和 `ChromaExperiment` 类。构造实验类时需要显式提供嵌入实现，Chroma 创建集合时设置 `embedding_function=None`，所有向量由调用方传入。默认启动不会导入 Chroma 或触发默认模型下载。

```bash
python -m pip install -r requirements-chroma.txt
```

可选依赖属于待联调扩展，未包含在默认测试覆盖中；请在独立环境内确认选定版本。接入顺序：

1. 选择团队允许的嵌入方案，实现 `embed_documents(texts)` 和 `embed_query(text)`。使用本地模型时先显式准备模型文件；使用远程服务时由环境变量提供密钥，禁止写进代码或资料。
2. 固定模型名称、向量维度和版本。文档与查询必须使用同一嵌入空间；改模型后重建向量库。
3. 分段后以 `chunk_id` 写入 Chroma，元数据至少保存课程、文档、资源、来源和原文位置。Chroma 的简单元数据不应直接写入知识点列表；需设计可过滤的字段表示或检索后校验策略，确保不能跨课程返回。
4. 为 JSON 原文存储与向量存储设计一致性机制；导入失败、覆盖和删除必须可重试。`ChromaExperiment.delete_resource` 仅删除向量，不会同步 JSON。
5. 扩展配置开关，在 `main.py` 显式选择检索后端，统一转换为当前 `Evidence` 响应；只有真实启用语义检索后才改 `mode`。
6. 检查距离指标和得分含义，不把 Chroma 距离直接伪装成当前关键词覆盖率。为向量分支补充课程隔离、删除、版本、空结果和引用一致性测试，再由 D 联调生成回答。

**当前未实现：**语义模型适配、HTTP 服务切换 Chroma、向量知识点过滤、向量与 JSON 同步恢复、真实 RAG 回答生成、重排序、PDF / Word 解析、OCR、正式鉴权、跨进程并发和完整课程评测。上述内容是后续任务，不是现成能力。
