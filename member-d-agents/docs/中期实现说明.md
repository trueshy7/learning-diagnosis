# D 模块中期实现说明（2026-11-14）

## 本次增量

在仓库原有的规则诊断骨架上补充三类能力：

1. 对 C 返回的证据按 B 的有效资源目录和目标知识点校验；不合法或重复的证据 ID 从报告剔除，并标记 `rag_invalid_evidence`。检索失败、空检索仍保留规则诊断。
2. 推荐只从当前课程、可用资源中选择，每个待改进知识点最多三条。近期用过的资源排后；优先有合法检索证据的资源，其次难度与稳定 ID。新增 `evidence_ids`、`estimated_minutes`、`next_step` 字段，旧请求不提供可选字段时仍可运行。
3. 增加可选 OpenAI Chat Completions 兼容适配器。默认 `LLM_MODE=disabled`，无模型密钥时不会发送请求。启用后模型只写独立的 `model_explanation`；规则统计、状态、资源 ID 和引用集合均由程序计算。输出须为限定 JSON，非法引用、格式错误、越界措辞及服务异常回退规则模板，`fallback_status` 与 `trace` 留痕。当前没有配置真实模型，因此没有声称模型效果或完成在线模型闭环。

## 调用合同与待确认点

B 继续调用 `POST /internal/diagnose-and-recommend`，现有必填字段保持不变。可选输入：`recent_resource_ids[]`；目录资源可增加 `course_id`、`available`、`difficulty`（1～5）、`estimated_minutes`。可选输出：`model_explanation`、`model_evidence_ids[]`；推荐项增加 `evidence_ids[]`、`next_step`、`estimated_minutes`。`mode=rule_template_demo` 表示规则模板，`mode=grounded_llm` 才表示本次有通过校验的模型建议。无匹配资源时返回空推荐，不补造资源。

D 不建设用户权限和业务数据库。B 需确认正式课程与题库，提供作废题、已提交空答、题目难度和最近推荐记录的可信字段；C 需确认资料版本与证据引用格式。当前六道题、两个知识点是联调样例，尚未达到任务书 8～12 知识点、60 题、20 资源的计划规模。后续要补充正式课程数据、真实模型调用验证、人工建议评分和 A 页面字段联调。

## DeepSeek 接入补充

用户选定 DeepSeek 后，D 新增 `LLM_MODE=deepseek`：固定官方 API 地址、默认 `deepseek-flash`，请求启用 JSON 输出并关闭思考模式，以便限定短建议；校验响应非空和未截断。密钥通过本机 `DEEPSEEK_API_KEY` 读取。`EXPECT_REAL_MODEL=1 python scripts/check_integration.py` 只有在真实模型文本通过证据约束且 C 的 HTTP 证据有效时才判定通过。当前仍缺真实密钥与运行记录，不能把模拟测试写作真实模型调用。
