# 成员 D 开发说明

## 一、负责的实际内容

本成员负责把后端已评分的作答转为知识点诊断结果，调用知识库检索，选择合法学习资源，并输出可展示、可追溯的报告。D 不负责前端页面、用户账户、数据库落库、试题评分或材料入库。

当前骨架已实现完整的确定性演示路径，便于先完成四人接口联调。后续“多智能体”工作在此基础上扩展；现阶段的三个 agent 是具名的逻辑阶段，由固定顺序调用，没有 LLM 推理。报告和健康检查一直标注 `rule_template_demo`。

## 三、数据流程与接口协作

1. A 将作答提交给 B。B 根据服务端题库评分，构造 `graded_answers`，不能直接相信前端提交的 `correct`。
2. B 调用 D 的 `POST /internal/diagnose-and-recommend`，传入作答、知识点表、资源目录及可选的前次统计。
3. D 诊断每个知识点。仅对 `weak` 或 `needs_practice` 的点触发检索与推荐。
4. D 在 `RAG_MODE=http` 下调用 C 的 `POST http://127.0.0.1:8001/internal/retrieve`。
5. D 输出普通 JSON 报告，不另加包装层。B 负责保存结果并转换为对 A 的公共 API 返回格式。

### B → D 请求

完整示例在 `examples/request.json`。必填字段为 `attempt_id`、`graded_answers`、`knowledge_points`、`resource_catalog`；`course_id` 默认 `course-ds`。

| 字段 | 内容与约束 |
| --- | --- |
| `graded_answers[]` | `question_id`、`knowledge_point_ids`、严格布尔值 `correct`；一题关联多个知识点时，每个点各计一次 |
| `knowledge_points[]` | `id`、`name`，ID 不能重复 |
| `resource_catalog[]` | `resource_id`、`title`、`knowledge_point_ids`，ID 不能重复；只从此目录产生推荐资源 ID |
| `baseline.knowledge_points[]` | 可选；上次报告的知识点统计，保留相同字段；准确率与状态必须符合计数和规则 |

相同 `question_id` 且评分、知识点集合相同的重复项只统计一次；同题评分或知识点集合矛盾时返回 422。未知知识点、目录重复 ID、互相矛盾的基线统计也返回 422。以 B 的数据库记录作为可信输入；这些校验不能替代身份鉴权或评分可信性检查。

### D → C 请求与响应

请求为普通 JSON：

```json
{"query":"栈 概念与练习","course_id":"course-ds","knowledge_point_ids":["kp-stack"],"top_k":5}
```

响应为普通 JSON：

```json
{
  "mode":"local_lexical_demo",
  "index_version":"demo-v1",
  "evidence":[
    {
      "evidence_id":"ev-stack-1",
      "document_id":"doc-stack",
      "resource_id":"res-stack",
      "chunk_id":"chunk-stack-1",
      "knowledge_point_ids":["kp-stack"],
      "text":"栈遵循后进先出原则。",
      "score":0.8,
      "location":"第 1 节",
      "source":"课程示例材料",
      "title":"栈示例材料"
    }
  ]
}
```

上面的响应仅说明字段形状，`mode` 与 `index_version` 由 C 实际返回。`location` 接受字符串或对象。D 原样保留证据引用字段，推荐资源 ID 始终与 B 的目录核对。没有目录匹配时不创造资源；空目录返回空推荐。

### D → B 报告

| 字段 | 含义 |
| --- | --- |
| `attempt_id`、`mode` | 作答标识与当前实现模式 |
| `knowledge_points[]` | 知识点 ID、名称、正确数、样本数、准确率及状态 |
| `evidence[]` | C 的证据，或明确标注 `builtin_mock_fixture` 的内置演示证据 |
| `recommendations[]` | 知识点 ID、合法资源 ID、目录标题、规则生成理由 |
| `explanation` | 当前能力、少样本限制、检索降级和复测解释 |
| `comparison[]` | 同知识点的前后准确率和差值；不能解释为因果提升 |
| `trace[]` | 依序记录 diagnosis、retrieval、recommendation 三阶段状态 |
| `fallback_status` | 正常为 null；失败时为 `rag_timeout`、`rag_unavailable`、`rag_http_状态码` 或 `rag_invalid_response` |

B 应保存 `evidence_id`、`document_id`、`chunk_id`、`resource_id`，使 A 的证据展示能追溯到材料。日志和报告避免记录用户姓名、密钥等与诊断无关的信息。

## 四、当前诊断与推荐规则

| 有效样本条件 | 准确率条件 | 状态 | 推荐 |
| --- | --- | --- | --- |
| 0 题 | `accuracy=null` | `insufficient_evidence` | 不生成 |
| 1～2 道不同题 | 显示实际准确率 | `insufficient_evidence` | 不生成 |
| 不少于 3 题 | 小于 0.6 | `weak` | 先处理 |
| 不少于 3 题 | 不小于 0.6 且小于 0.8 | `needs_practice` | 后处理 |
| 不少于 3 题 | 不小于 0.8 | `mastered` | 不生成 |

准确率以每个知识点的不同题为分母；一题的多个关联知识点分别等权计数，不按难度或题型加权。准确率保留 6 位小数，状态判断使用原始计数比例。该规则只表示本次测验表现，不能替代教育测量意义上的能力估计。

每个可推荐知识点最多选一项资源。优先目录中被检索命中的资源，再按资源 ID 稳定排序。知识点薄弱优先，其次待巩固；相同条件保持输入次序。未检索到证据时，仅生成注明“尚无匹配检索证据”的目录建议。默认 mock 证据也只用于展示接口，不意味着知识库已经建好。

复测仅比较相同知识点且前后样本均不少于 3 题的准确率；前次或本次证据不足则不输出比较项。差值允许正、零、负，不自动宣称学习提升，也不把变化归因于推荐。

## 五、运行配置与异常处理

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `RAG_MODE` | `mock` | `mock` 为自编内置片段，`http` 为调用 C；其他值属于配置错误 |
| `RAG_BASE_URL` | `http://127.0.0.1:8001` | 仅在 http 模式使用，由部署者设置，不能取自用户请求 |
| `RAG_TIMEOUT_SECONDS` | `5` | http 超时，必须为正数 |

本服务不需要 LLM 密钥。复制 `.env.example` 为 `.env` 后，程序通过 `python-dotenv` 读取启动目录的 `.env`，操作系统环境变量优先；请在项目目录启动，修改配置后重启。D 服务使用 8002，C 使用 8001，B 使用 8000；A 通过 B 访问，不直接把内部 D 接口暴露给浏览器。

HTTP 检索失败时保留诊断统计，`evidence=[]`，明确记录 `fallback_status`；不会悄悄改用 mock 或伪造检索成功。输入校验错误返回 422。模型接入未实现，不应开启虚假的模型开关或编造模型生成结果。

## 七、后续扩展的明确边界

后续工作包括更丰富的题目难度与错因模型、基于实际课程数据校准阈值、按学习目标调整推荐，以及真实 LLM 的结构化解释适配。若接入真实模型，应固定允许的知识点和资源 ID、验证输出 JSON、限制引用只能来自给定证据、保留错误降级和调用记录。模型输出只能辅助解释，不能覆盖可信评分或把无依据的文本当作证据。

当前骨架没有持久化、身份鉴权、任务队列、在线模型调用、自动规划、学习成效评估实验或生产监控。这些由后续任务逐步实现；课程演示时应按实际完成情况陈述。
